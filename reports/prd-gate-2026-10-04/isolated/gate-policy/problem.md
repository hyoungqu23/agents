# 내부 문서 검토에서 의도한 리비전 열기

## 사용자와 상황

내부 문서 담당자는 매주 검토를 위해 동료들에게 문서를 PDF로 내보내 전달한다. 검토 후 원본 문서가 변경되며, 수신자는 이전에 받은 내보내기 파일을 보관할 수 있다. 영향을 받는 역할은 문서를 전달하는 담당자와 이를 열어 검토하는 내부 동료다. [EV-001]

## 현재 행동과 문제

현재 담당자는 PDF 파일명에 리비전 표시를 붙이고, 내용이 바뀌면 교체 첨부파일을 다시 보낸다. [EV-003] 이 방식에서는 변경된 원본과 수신자가 보관한 PDF가 서로 다른 리비전일 수 있다. 제공된 메모에는 지난주 수신자 12명 중 4명이 오래된 버전을 열었다고 기록되어 있다. [EV-001, EV-002]

**문제는 원본이 바뀐 뒤 내부 수신자가 문서를 열 때, 전달자가 의도한 리비전 대신 오래된 내보내기 파일을 열 수 있다는 점이다.** 사용자가 탐색하려는 것은 기존 내부 사용자가 현재 문서에 접근하는 것이며, 문제 정의의 초점은 수신자가 의도한 리비전을 여는 결과에 둔다. 특정 공유 기능이나 UI가 이 문제를 해결한다고 확정하지 않는다. [EV-002, DEC-001, DEC-003]

## 근거와 한계

아래 근거는 SRC-001의 서두와 `User-provided context`에 있다. 이 파일은 스킬 평가용 합성 입력이며 실제 고객 조사나 독립 검증 결과가 아니다. [EV-000]

| ID | 입력에서 확인한 내용과 위치 |
| --- | --- |
| EV-000 | SRC-001 서두: 이름과 수치는 평가용 합성 입력이며 검증했다고 주장해서는 안 된다고 명시한다. |
| EV-001 | SRC-001 `User-provided context` 첫 문단: 주간 PDF 전달, 검토 후 원본 변경, 수신자의 과거 파일 보관 가능성. |
| EV-002 | 같은 첫 문단: 지난주 수신자 **12명 중 4명**이 오래된 버전을 열었다는 보고. 독립 검증되지 않았고 과거 기준선도 없다. |
| EV-003 | 같은 절 `Current workaround` 문단: 파일명에 리비전을 표시하고 변경 시 교체 첨부파일을 전달한다. 팀에는 이미 로그인 계정이 있다. |

이 입력만으로 반복 빈도, 긴급성, 원인별 기여도는 확정할 수 없다. 연간 비용, 매출, 손실 시간, 유지율 영향도 추정하지 않는다. 문제 정의를 위해 추가 가정을 사실처럼 채우지 않았으며, 별도 AS 항목은 두지 않는다.
