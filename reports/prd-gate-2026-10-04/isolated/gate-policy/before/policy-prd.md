# 내부 문서 검토에서 의도한 리비전 열기 — PRD

## 1. 문제와 근거

내부 문서 담당자는 매주 동료에게 PDF를 전달한다. 검토 후 원본이 변경되어도 수신자는 이전 내보내기 파일을 보관할 수 있다. 현재는 PDF 파일명에 리비전을 표시하고 변경 시 교체 첨부파일을 다시 보낸다. 해결하려는 문제는 원본 변경 후 수신자가 전달자의 의도와 다른 오래된 리비전을 여는 것이다. [EV-001, EV-002, EV-003]

상위 문제 정의는 revision 1, `ready_for_review`다. 이는 문제 정의를 검토할 수 있다는 뜻이며, 해결책의 효과나 구현 승인을 뜻하지 않는다. 아래 근거와 결정의 ID는 상위 문서에서 유지했다. 원자료인 SRC-001도 직접 읽었다.

| ID | 근거와 출처 | 한계 |
| --- | --- | --- |
| EV-000 | SRC-001 서두: 이름과 수치는 스킬 평가용 합성 입력이다. | 실제 고객 조사나 독립 검증 결과가 아니다. |
| EV-001 | SRC-001 `User-provided context` 첫 문단: 주간 PDF 전달, 검토 후 원본 변경, 과거 파일 보관 가능성. | 실제 이용 행태를 이번 작업에서 관찰하지 않았다. |
| EV-002 | 같은 문단: 지난주 수신자 **12명 중 4명**이 오래된 버전을 열었다는 보고. | 독립 검증과 과거 기준선이 없다. 반복 빈도나 개선 목표로 일반화하지 않는다. |
| EV-003 | SRC-001 `Current workaround`: 파일명 리비전 표시 및 교체 첨부파일 전달. 팀에는 기존 로그인 계정이 있다. | 기존 계정의 문서별 접근 권한 정책은 제공되지 않았다. |

연간 비용, 매출, 손실 시간, 유지율 영향, 긴급성 또는 원인별 기여도는 추정하지 않는다. 특정 공유 기능이 문제를 해결한다는 근거도 아직 없다. [EV-000–EV-003]

## 2. 사용자와 목표

사용자는 검토 문서를 전달하는 내부 문서 담당자와, 이를 열어 검토하는 기존 내부 동료다. 핵심 상황은 문서 전달 이후 원본이 변경되고 수신자가 다시 문서를 여는 때다. [EV-001, DEC-001]

| ID | 목표 | 성공 관찰 |
| --- | --- | --- |
| GOAL-001 | 내부 수신자가 검토 시 전달자가 의도한 리비전을 연다. [DEC-003] | 해당 검토에서 의도한 리비전과 실제 열린 리비전을 대조한다. 일치 여부가 최초 관찰 결과다. |
| GOAL-002 | 기존 내부 사용자가 현재 문서에 접근할 수 있다. [DEC-001] | 대상 내부 사용자가 합의된 접근 조건에서 문서를 열 수 있는지 관찰한다. 문서별 권한 조건은 OD-005에 달려 있다. |

주간 검토에서 두 리비전을 대조하고, 불일치 시 어떤 파일·전달 경로로 열었는지 함께 확인하는 것을 관찰 방법으로 제안한다. 이는 측정 완료나 제품 내 분석 기능 요구가 아니다. 수치 목표, 표본 크기, 측정 도구는 합의되지 않았으며 임의로 정하지 않는다. [SRC-002 `열린 결정과 다음 근거`, DEC-003]

## 3. 결정과 범위

| ID | 유지하는 결정 | 출처 및 적용 |
| --- | --- | --- |
| DEC-001 | 현재 문서 접근은 기존 내부 사용자만 대상으로 탐색한다. 익명 공유와 새 로그인 구현은 범위 밖이다. | SRC-001 `User decision`; SRC-002 `원하는 결과와 범위`. |
| DEC-002 | 링크 만료, 복사·내보내기 제한, 접근 철회 동작은 추가 논의한다. | 같은 위치. 이번 PRD에서도 기본 정책을 선택하지 않는다. |
| DEC-003 | 첫 성공 관찰은 의도한 리비전을 여는지로 한다. 임의 개선율 목표를 만들지 않는다. | 같은 위치. |
| DEC-004 | 이전 산출물은 문제 정의이며 UI·데이터베이스 제안을 작성하지 않는다. | SRC-001 마지막 문단; SRC-002 DEC-004. 이전 단계의 범위 결정으로 보존한다. |
| DEC-005 | 이번 산출물은 제공된 결정·근거·미결정을 유지한 `prd.md`이며, 질문 없이 로컬 입력만 사용한다. | SRC-003. 현재 문서의 산출물 범위는 PRD로 확장하되 UI·데이터베이스 설계는 추가하지 않는다. |

현재 범위는 기존 내부 사용자의 문서 접근과 의도한 리비전 열기에 대한 사용자 결과 및 수용 기준이다. 전달 수단이나 화면은 확정하지 않는다. 익명 공유, 새 로그인 구현, UI/API/데이터베이스 설계는 범위 밖이다. 만료·복사/내보내기·철회는 미결정이며, 제외하거나 무제한 허용하기로 결정한 것이 아니다. [DEC-001, DEC-002, DEC-005]

## 4. 주요 시나리오

1. **정상 검토:** 문서 담당자가 의도한 리비전을 기준으로, 접근이 허용된 기존 내부 수신자가 문서를 연다. 실제 열린 리비전이 의도한 리비전과 일치해야 한다. [GOAL-001, FR-001]
2. **전달 후 원본 변경:** 기존 수신자가 다시 열 때 어떤 리비전을 의도한 것으로 볼지는 OD-004에서 정한다. 최신 리비전 자동 선택이나 전달 시점 리비전 고정을 임의로 채택하지 않는다. [EV-001, EV-002]
3. **과거 PDF 이용:** 수신자가 보관한 PDF를 열었다면 의도한 리비전과 대조하여 불일치를 관찰한다. 이미 보관된 파일을 자동 갱신·삭제하거나 이용을 차단한다는 요구는 확정하지 않는다. [EV-003, OD-002]
4. **익명 또는 외부 사용자 접근:** 이번 범위의 문서 접근은 허용되지 않는다. 기존 내부 사용자라도 해당 문서의 허용 대상인지 결정하는 규칙은 OD-005로 남긴다. [DEC-001, FR-003]
5. **열기 실패 또는 정책 경계:** 의도한 리비전을 열지 못한 경우 성공 기준을 충족하지 않는다. 대체 리비전 처리와 실패 안내는 OD-006, 만료 및 철회 이후 동작은 OD-001·OD-003에 따라 확정해야 한다.

## 5. 요구사항과 수용 기준

아래 기준은 사용자 결과를 구체화한 초안이다. OD가 연결된 조건의 전체 검증은 해당 결정 이후에 가능하며, 현재 통과했다고 주장하지 않는다.

| 요구사항 | 수용 기준 | 근거·의존성 |
| --- | --- | --- |
| FR-001: 접근이 허용된 기존 내부 수신자가 의도한 리비전을 열 수 있어야 한다. | AC-001: 담당자의 의도한 리비전과 접근 허용 조건이 정해진 상태에서 수신자가 문서를 열면, 실제 열린 리비전이 의도한 리비전과 일치한다. | GOAL-001, DEC-003; 의도한 리비전의 선택 규칙은 OD-004, 권한 조건은 OD-005. |
| FR-002: 원본 변경 후 다시 여는 상황에서도 의도한 리비전 일치 여부를 충족해야 한다. | AC-002: 전달 이후 원본이 변경된 조건에서 OD-004로 합의한 의도한 리비전과 재접근 시 실제 열린 리비전이 일치한다. 과거 파일이 열려 불일치하면 성공으로 판정하지 않는다. | GOAL-001, EV-001, EV-002; OD-004 결정 전 기대 리비전을 임의로 지정하지 않는다. |
| FR-003: 문서 접근 대상은 기존 내부 사용자로 제한한다. | AC-003: 익명 사용자 또는 기존 내부 사용자에 해당하지 않는 사용자가 이번 기능으로 접근을 시도하면 문서 내용을 열 수 없다. 차단 안내 방식은 지정하지 않는다. | GOAL-002, DEC-001. 내부 사용자 전체에게 모든 문서 권한을 부여한다는 뜻은 아니다. |
| FR-004: 기존 계정을 가진 접근 허용 대상자가 새 로그인 구현 없이 현재 문서에 접근할 수 있어야 한다. | AC-004: 허용 대상 내부 사용자가 기존 로그인 계정을 이용하는 조건에서 문서를 열 수 있다. 이 결과를 위해 새로운 로그인 체계를 구현하는 것을 완료 조건으로 요구하지 않는다. | GOAL-002, EV-003, DEC-001; 문서별 허용 대상은 OD-005. |

만료·복사/내보내기·철회 및 열기 실패의 구체 동작에 대한 FR/AC는 정책 결정 이후 추가한다. 빈 문서의 취급도 입력에 정의되어 있지 않아 별도 동작을 만들어 넣지 않는다. [DEC-002, OD-001–OD-003, OD-006]

## 6. 제약과 의존성

- 기존 로그인 계정이 있다는 조건에 의존한다. 계정 존재만으로 문서별 권한이 정해졌다고 해석하지 않는다. [EV-003, OD-005]
- 링크 사용은 아직 확정된 해결책이 아니다. OD-001은 링크를 통한 접근을 선택할 경우 적용할 정책 결정이다. [SRC-002 OD-001]
- 과거 PDF 사본이 남을 수 있으므로, 새로운 접근 결과의 성공과 기존 사본의 이용 통제는 구분해야 한다. 사본 통제 범위는 OD-002에서 결정한다. [EV-001, DEC-002]
- 구체 전달 방식, 화면, 기술 구조, 출시 일정은 제공되지 않았으며 이 PRD에서 확정하지 않는다.

## 7. 가정과 열린 결정

정책이나 해결책의 효과를 미검증 가정으로 채택하지 않았다. 별도 AS 항목은 없다. 불명확한 제품 동작은 아래 OD로 유지한다. OD-001–OD-003은 상위 ID를 보존하고, OD-004–OD-006은 요구사항 작성 중 드러난 질문으로 추가했다. 새 질문은 사용자가 이미 결정한 내용이 아니다.

| ID | 미결정 사항과 영향 | 차단·유보 범위 | 재논의 조건 |
| --- | --- | --- | --- |
| OD-001 | 링크 만료 여부와 조건. 접근 가능 기간에 영향을 준다. [DEC-002] | PRD 초안 저장은 막지 않지만 해당 만료 요구사항 확정을 막는다. | 링크 접근을 검토하고 유효기간 동작을 정하기 전. |
| OD-002 | 복사·내보내기 제한 여부와 범위. 별도 사본 생성·보관·이용에 영향을 준다. [DEC-002] | 사본 관련 요구사항 확정을 막는다. 허용/금지 기본값 모두 유보한다. | 사본 생성과 원본 변경 후 이용 방식을 정하기 전. |
| OD-003 | 접근 철회 시 어떤 접근이 가능한지. [DEC-002] | 철회 이후 동작과 수용 기준 확정을 막는다. | 접근 철회 요구사항을 정하기 전. |
| OD-004 | 원본 변경 후 ‘의도한 리비전’의 기준과 이를 정하는 시점·주체. 현재 문서 접근이라는 방향만으로 항상 최신 또는 전달 시점 고정 중 하나를 확정할 수 없다. [DEC-001, DEC-003] | FR-001·FR-002의 기대 리비전, 특히 변경 후 AC-002의 확정을 막는다. | 변경 전후 재접근 사례의 기대 리비전을 정하기 전. |
| OD-005 | 기존 내부 사용자 중 문서별 접근 허용 대상을 정하는 규칙. 기존 계정과 문서 권한의 관계가 불명확하다. [EV-003, DEC-001] | 내부 사용자 허용·거부 분기와 AC-001·AC-004의 권한 조건 확정을 막는다. | 내부 사용자별 허용/거부 사례를 확정하기 전. |
| OD-006 | 의도한 리비전을 사용할 수 없거나 열기에 실패할 때의 결과 및 대체 리비전 처리. [GOAL-001에서 도출] | 실패·빈 콘텐츠 관련 구체 요구사항 확정을 막는다. 대체본을 성공으로 간주할 수는 없다. | 열기 실패 또는 이용 불가 리비전의 수용 기준을 작성하기 전. |

추가로 필요한 근거는 실제 검토에서 의도한 리비전과 열린 리비전의 대조, 불일치 경로에 관한 관찰이다. 해결책 효과와 실제 수요는 검증되지 않았다. 이 근거 공백을 임의 수치나 개선율로 메우지 않는다. [EV-000, EV-002, DEC-003]

## 8. 성숙도와 변경 이력

`needs_decision`: 문제와 사용자 결과는 출처에 연결된 요구사항으로 작성했지만, 리비전 선택 기준과 권한 조건, 명시적으로 유보된 정책이 남아 있어 전체 동작과 수용 기준을 확정할 수 없다. 질문 없이 가능한 초안을 저장했으며, 구현 승인이나 독립 PRD 검토 통과를 의미하지 않는다. 외부 조회나 실제 측정은 수행하지 않았다.

| 리비전 | 변경 |
| --- | --- |
| 1 | SRC-001 및 상위 문제 정의 revision 1을 기반으로 신규 PRD 작성. EV-000–EV-003, DEC-001–DEC-004, OD-001–OD-003의 의미와 ID 보존. 현재 요청 DEC-005, GOAL-001–GOAL-002, FR-001–FR-004, AC-001–AC-004 및 OD-004–OD-006 추가. 기존 주장 삭제·대체 없음. |
