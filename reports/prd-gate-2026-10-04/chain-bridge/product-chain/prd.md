# 제품 요구사항: 기존 태그로 읽기 노트 찾기

## 문제와 근거

개인 사용자는 기존 태그로 읽기 노트를 찾을 때 무관한 노트를 반복해서 열고, 현재 노트 목록을 훑는다고 보고한다(problem.md / EV-002; SRC-001 “I keep existing reading notes”부터 “scan the note list”까지). 이 PRD는 실제 작성된 problem:personal-tag-lookup revision 1 및 원자료를 기반으로 한다. 상위 문서는 ready_for_review이며, 원자료는 합성 평가 입력으로 고객 조사나 측정 결과가 아니다(problem.md / EV-001; SRC-001 첫 문장).

아래 EV/AS/DEC 참조는 problem.md에 정의된 동일한 주장의 ID를 유지한다. 사용자의 필요는 선택한 기존 태그에 해당하는 노트만 정확히 찾아 저장된 내용을 여는 것이다(DEC-001).

## 목표와 관찰 방법

- GOAL-001 — 선택한 기존 태그가 붙은 노트 집합을 정확하게 찾는다(EV-002, DEC-001). 추후 검증에서는 기존 데이터의 태그 관계와 조회 결과를 비교하여 누락과 무관한 노트 포함 여부를 관찰한다.
- GOAL-002 — 조회된 노트의 저장된 내용을 열어 확인한다(DEC-001). 추후 검증에서는 선택한 결과 노트와 열린 내용의 대응을 확인한다.
- GOAL-003 — 정상적인 빈 결과와 조회 실패를 사용자가 구별한다(DEC-003). 추후 검증에서는 두 조건에서 나타나는 상태를 비교한다.

이들은 검증 계획이며 수행 결과가 아니다. 정량적 속도 목표는 두지 않는다(DEC-002).

## 범위와 다음 단계

기존 태그 선택, 해당 태그의 기존 노트 조회, 결과 노트의 저장된 내용 열기, 빈 결과와 실패 구별을 다룬다. 대상은 기존 노트·태그를 보유한 개인 사용자다(DEC-001~003).

태그 편집, 팀 공유, 새로운 인증은 제외한다. 레이아웃·아키텍처·저장 방식은 이 문서에서 결정하지 않는다. 다음 단계의 범위는 선택·열기·빈 결과·실패 사용자 흐름 설계다(DEC-002, DEC-004). 별도 권한 정책이나 데이터 갱신 정책을 새로 만들지 않는다. 원자료에 그러한 동작의 필요나 제약이 제시되지 않았다.

## 시나리오와 요구사항

| 요구사항 | 관찰 가능한 수용 기준 | 추적 근거 |
| --- | --- | --- |
| FR-001 — 사용자는 기존 태그를 선택하여 그 태그의 노트를 조회할 수 있다. | AC-001 — 기존 태그 T를 선택하고 조회가 성공하면, 결과 노트 집합은 기존 데이터에서 정확한 태그 T가 붙은 모든 노트의 집합과 같다. 해당하지 않는 노트는 포함되지 않고 해당 노트는 누락되지 않는다. 여러 태그를 가진 노트도 T를 포함하면 결과에 속한다. | GOAL-001, DEC-001, AS-001; SRC-001 “returns exactly the existing notes” |
| FR-002 — 조회 결과에서 노트를 선택하면 그 노트의 저장된 내용을 열 수 있다. | AC-002 — 조회 성공 결과에 있는 노트 N을 선택하고 내용 읽기가 성공하면 N의 저장된 내용이 열리며 다른 노트의 내용으로 대체되지 않는다. | GOAL-002, DEC-001, AS-001; SRC-001 “lets me open their stored content” |
| FR-003 — 성공한 조회에 일치 노트가 없으면 빈 결과임을 알 수 있다. | AC-003 — 기존 태그 T의 조회가 성공하고 T가 붙은 노트가 없으면 일치하는 노트가 없다는 상태가 보인다. 이 상태는 조회 실패 상태와 눈에 보이게 구분된다. | GOAL-003, DEC-003; SRC-001 “An empty lookup” |
| FR-004 — 조회가 실패하면 실패임을 알 수 있다. | AC-004 — 선택한 태그의 조회가 실패하면 실패 상태가 보이며, 정상 조회에서 일치 노트가 없다는 상태로 표시되지 않는다. | GOAL-003, DEC-003; SRC-001 “distinct from a failed lookup” |

정상 시나리오는 기존 태그 선택 → 정확한 결과 확인 → 결과 노트 선택 → 저장된 내용 확인이다(FR-001~002). 조회가 성공했으나 일치 노트가 없으면 빈 결과 흐름(FR-003), 조회 자체가 실패하면 실패 흐름(FR-004)으로 나뉜다. 이 구분은 동작의 의미를 정하며 화면 배치나 기술적 처리 방식을 정하지 않는다.

## 의존성, 가정과 미해결 사항

AS-001을 그대로 유지한다: 기존 노트·태그 관계 및 저장된 내용은 읽을 수 있다고 가정하지만 실제 통합은 확인하지 않았다(problem.md / AS-001; SRC-001 “whether the existing data can be read”). 이 가정은 선언된 다음 흐름 설계에는 비차단이며 제품 정책 선택으로 바꾸지 않는다(DEC-005). 통합 검토 시 실제 데이터 읽기를 확인하고, 실패하거나 새 제약이 발견되어 동작이 달라져야 한다면 구현 가능성과 관련 요구사항을 재검토한다. 저장된 내용 열기 실패의 구체적 처리 또한 실제 읽기 제약을 확인할 때 검토할 수 있으며 현재 새 정책을 임의로 확정하지 않는다.

현재 좁은 흐름 범위에 미해결 제품 정책 결정(OD)은 없다(DEC-005; SRC-001 “No blocking product policy choice remains”). 시장 검증이나 수치 목표를 추가로 요구하지 않는다.

## 성숙도와 제한

ready_for_review: 요구사항과 수용 기준을 원자료 및 상위 문제 정의에 연결했고, 선언된 흐름 범위에서 검토할 수 있다. 독립 검토 결과나 흐름 설계 승인, 구현 승인을 뜻하지 않는다. 통합 가능성, 실제 사용 효과, 시장 수요 및 측정 결과는 검증하지 않았다. 신규 revision 1이므로 변경 이력은 없다.
