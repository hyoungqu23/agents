# 기존 태그로 독서 노트 찾기 — 제품 요구사항

## 문제와 근거

개인이 기존 독서 노트에서 선택한 기존 태그의 노트를 찾을 때 관련 없는 노트를 반복해서 열고, 현재는 목록을 훑는다는 서술이 출발점이다. 이 입력은 합성 평가 자료이며 실제 고객 연구, 사용 빈도, 속도 측정 또는 시장 검증이 아니다. 기존 태그에 해당하는 노트를 정확히 찾고 그 저장된 내용을 열 수 있게 하는 것이 요청된 결과다. [SRC-001, problem.md / EV-001, EV-002, DEC-001]

상위 문제 정의 revision 1은 `ready_for_review`이며 문제·범위가 정리된 상태이지 효과나 구현 가능성이 검증된 상태가 아니다. 아래 EV/DEC/AS 참조는 `problem.md`의 동일한 ID와 의미를 유지한다. 원자료와 상위 문서를 모두 읽어 작성했다.

## 목표와 성공 관찰

- **GOAL-001** — 개인이 선택한 기존 태그를 가진 기존 노트만 빠짐없이 확인하고 원하는 노트의 저장된 내용을 연다. 확인 방법은 기존 태그 연결로 기대되는 노트 집합과 실제 결과를 대조하고, 연 내용이 선택한 노트의 저장된 내용인지 대조하는 것이다. [EV-002, DEC-001]
- **GOAL-002** — 조회가 성공했지만 결과가 없는 경우와 조회 실패를 사용자가 구별한다. 두 상황에서 보이는 상태를 비교해 구별 가능 여부를 확인한다. [DEC-003]

이는 이후 수행할 수용 확인 방법이며 수행 결과가 아니다. 정량 속도 목표와 시장 지표는 설정하지 않는다. [EV-001, DEC-002, DEC-005]

## 범위와 제외

범위는 기존 태그 선택, 그 태그가 붙은 기존 노트 조회, 결과 노트의 저장된 내용 열기, 빈 결과와 실패의 구별이다. 다음 작업은 이 범위의 select/open/empty/failure 사용자 흐름 설계다. [DEC-001, DEC-003, DEC-004]

태그 편집, 팀 공유, 신규 인증, 정량 속도 목표는 제외한다. 노트나 태그 생성도 기존 데이터 조회 범위에 포함하지 않는다. 레이아웃, 아키텍처, 저장 방식은 결정하지 않는다. 별도 권한·공유 정책이나 검색 확장 규칙을 추가하지 않는다. [DEC-002, DEC-004]

## 요구사항과 수용 기준

### FR-001 — 기존 태그 선택과 정확한 결과

개인은 기존 태그 하나를 선택하여 그 태그가 실제로 붙어 있는 기존 노트를 조회할 수 있다. 결과는 해당 노트 집합과 정확히 같아야 한다. [GOAL-001, DEC-001, AS-001]

- **AC-001** — 읽을 수 있는 기존 데이터와 기존 태그 T가 있고 T가 붙은 노트가 하나 이상 있을 때, T를 선택하여 조회에 성공하면 T가 붙은 모든 기존 노트가 결과에 포함되고 T가 없는 노트는 포함되지 않는다. 유사한 이름의 다른 태그만 가진 노트도 포함되지 않는다. [FR-001, DEC-001]
- **AC-002** — 다른 기존 태그 U를 선택하여 조회에 성공하면 결과 집합은 U에 해당해야 한다. 이전 T의 결과 중 U가 없는 노트를 현재 결과로 제시하지 않는다. [FR-001, DEC-001]

### FR-002 — 결과 노트의 저장된 내용 열기

개인은 반환된 노트를 선택해 그 노트의 저장된 내용을 열 수 있다. [GOAL-001, DEC-001, AS-001]

- **AC-003** — 조회 결과에 있는 노트 N을 선택하고 내용 읽기에 성공하면 N의 저장된 내용이 열리며, 다른 노트의 내용으로 대체되지 않는다. [FR-002, DEC-001]
- **AC-004** — 선택한 노트의 내용을 읽지 못하면 내용 열기에 실패했음을 알 수 있어야 하며, 다른 노트의 내용이나 내용 없는 성공으로 제시하지 않는다. 구체적인 표현과 복구 동작은 후속 흐름 설계에서 다룬다. [FR-002, DEC-001, DEC-004, AS-001]

### FR-003 — 빈 조회와 조회 실패 구분

조회 성공 시 일치 노트가 없는 상태와 조회 자체가 실패한 상태를 눈에 보이게 구분한다. [GOAL-002, DEC-003]

- **AC-005** — 선택한 기존 태그에 해당하는 노트가 없고 조회가 성공하면 일치하는 노트가 없음을 확인할 수 있다. 이는 실패 상태와 구별된다. [FR-003, DEC-003]
- **AC-006** — 선택 태그의 노트 조회가 실패하면 조회 실패임을 확인할 수 있다. 이를 성공한 빈 결과 또는 해당 태그의 노트가 없다는 확정으로 표시하지 않는다. [FR-003, DEC-003]

정상 시나리오는 기존 태그 선택 → 해당 노트 확인 → 선택 노트 내용 열기다. 분기는 성공한 빈 조회, 조회 실패, 내용 열기 실패이며 위 기준으로 관찰한다. 화면 배치, 오류 문구, 데이터 저장 구조는 수용 기준에 포함하지 않는다. [FR-001–FR-003, DEC-004]

## 의존성, 가정과 미결정 사항

- **AS-001 (상위에서 유지)** — 기존 노트·정확한 태그 연결·저장된 내용을 읽을 수 있다고 가정한다. 실제 데이터와 연동 수단은 제공되지 않았다. 가정이 틀리면 FR-001/FR-002의 실제 제공이 막힌다. 이후 통합 확인에서 읽기와 원본 대조로 확인한다. 아직 확인하지 않았다. [problem.md / AS-001, SRC-001의 “integration assumption to check later”]

사용자는 좁은 흐름 범위에 차단하는 제품 정책 선택이 남아 있지 않다고 명시했다. 따라서 데이터 읽기 가능성을 새 제품 정책 OD로 바꾸지 않는다. 현재 실제 미결정 제품 선택이 없으므로 OD 항목은 없다. 통합 확인 실패나 새 정책 제약 발견 시 영향과 차단 여부를 재평가한다. [DEC-005, AS-001]

## 문서 성숙도와 한계

`ready_for_review`는 요구사항과 관찰 가능한 수용 기준을 원자료에 연결하여 검토할 수 있다는 의미다. 합성 자료 밖의 사용자 연구, 데이터 접근, 실행 테스트, 속도 측정은 수행하지 않았다. 구현 승인 또는 독립 게이트 판정을 의미하지 않는다. 신규 revision 1이며 이전 변경 이력은 없다.
