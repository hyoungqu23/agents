# 개인 독서 노트 PRD

## 문제와 근거

소유자가 독서 노트에 출처 참조를 붙이고, 자신이 선택한 태그로 해당 노트를 다시 찾는 개인용 도구를 정의한다. 입력은 제안된 개인 작업 흐름이며, 현재 불편의 빈도나 기존 대안, 실제 사용 결과는 제공되지 않았다. 고객 수요가 검증되었다고 해석하지 않는다.

- **EV-001** — SRC-001 첫 문장에는 소유자가 노트에 출처 참조를 첨부하고 선택한 태그로 노트를 찾으려는 요구가 있다. 이는 요구의 근거이지 관찰된 성과가 아니다.
- **EV-002** — SRC-001 두 번째 문장은 개인 작업 흐름 제안이며 검증된 고객 수요가 아니라고 명시한다.
- **DEC-001** — 개인 소유자의 출처 첨부와 태그 기반 재탐색을 이번 요구사항 범위로 삼는다. 근거: SRC-001 첫 두 문장.
- **DEC-002** — 팀 공유, 새로운 인증, 출시일은 범위에서 제외한다. 근거: SRC-001 세 번째 문장.
- **DEC-003** — 질문 없이 초안을 작성하고 상위 문제 문서를 만들지 않는다. 제공된 로컬 입력만 사용해 `prd.md`에 저장한다. 근거: SRC-001 마지막 문장, SRC-002.

상위 문서는 제공되지 않아 `depends_on`은 비어 있다. 상태는 **needs_decision**이다. 출처 참조의 허용 범위와 태그 일치 규칙 등 수용 판정에 영향을 주는 선택이 미정이다. 문서 검토는 가능하지만 구현 승인이나 독립 PRD 검토 완료를 뜻하지 않는다.

## 사용자와 사용 상황

사용자는 개인 독서 노트 도구의 소유자다. 독서 중 또는 이후 노트에 출처를 남기고, 나중에 선택한 태그로 관련 노트를 다시 찾는다. 노트를 최초로 만드는 방식과 기존 노트의 유입 경로는 입력에 없다. 아래 시나리오는 사용할 노트가 이미 존재하는 조건에서 시작한다. (EV-001, AS-001)

## 목표와 성공 관찰

| ID | 사용자 목표 | 확인할 수 있는 결과 | 근거 |
| --- | --- | --- | --- |
| GOAL-001 | 노트의 출처를 남긴다. | 출처를 첨부한 노트를 다시 열면 해당 참조를 확인할 수 있다. | EV-001, DEC-001 |
| GOAL-002 | 선택한 태그로 노트를 다시 찾는다. | 태그가 연결된 노트를 그 태그로 찾고 열 수 있다. | EV-001, DEC-001 |

위 결과는 향후 동작 확인 기준이며 측정 결과가 아니다. 수치 성능 목표는 정해지지 않았다. 응답 시간 기준이나 성공률을 임의로 부여하지 않는다. (OD-004)

## 범위와 제외 사항

이번 초안은 기존 노트에 출처 참조를 첨부·확인하는 동작, 노트와 태그의 연결, 선택한 태그를 통한 재탐색을 다룬다. 태그 연결은 재탐색을 가능하게 하기 위한 초안 가정이다. (DEC-001, AS-002)

팀 공유, 새로운 인증, 출시일은 명시적으로 제외한다. 삭제 동작은 미결정 상태로 별도 보류하며, 삭제 허용·금지 또는 복구 방식을 정하지 않는다. 화면 구성, API, 저장 구조는 이 문서에서 결정하지 않는다. (DEC-002, OD-003)

## 주요 시나리오

1. **출처 남기기:** 소유자가 기존 노트에 출처 참조를 첨부한다. 완료 후 노트를 다시 열어 같은 참조를 확인한다. (GOAL-001)
2. **태그로 다시 찾기:** 소유자가 노트에 연결된 태그를 선택한다. 해당 노트를 결과에서 확인하고 연다. (GOAL-002, AS-002)
3. **일치 결과 없음:** 선택한 태그에 해당하는 노트가 없으면 결과가 없다는 사실을 구분할 수 있다. (GOAL-002)
4. **첨부 또는 탐색 실패:** 작업이 실패하면 성공이나 일치 결과 없음으로 표시하지 않는다. 소유자는 작업이 완료되지 않았음을 알 수 있다. (GOAL-001, GOAL-002)

## 기능 요구사항과 수용 기준

다음은 입력의 사용자 결과를 관찰 가능한 동작으로 풀어 쓴 초안이다. 미정 정책에 의존하는 기준은 그 결정을 명시한다.

### FR-001 — 출처 참조 첨부와 확인

소유자는 노트에 출처 참조를 첨부하고, 이후 해당 노트에서 확인할 수 있어야 한다. (GOAL-001, EV-001)

- **AC-001:** 기존 노트에 허용된 출처 참조를 첨부하여 완료한 후 노트를 다시 열면 첨부한 참조를 확인할 수 있다. 허용 형식과 내용 보존 기준은 OD-001 결정 후 구체화한다.
- **AC-002:** 참조 첨부가 실패한 경우 완료되었다고 표시하지 않고 실패를 알린다.

### FR-002 — 노트와 태그 연결

소유자는 이후 재탐색에 사용할 태그를 노트에 연결할 수 있어야 한다. 이 요구는 입력에 명시되지 않은 연결 수단을 보완하는 가정에 의존한다. (GOAL-002, AS-002)

- **AC-003:** 소유자가 기존 노트에 태그를 연결하여 완료하면, 해당 태그를 선택해 찾을 때 그 노트가 결과에 포함된다. 태그 생성·선택 방식과 일치 규칙은 OD-002 결정 후 구체화한다.

### FR-003 — 선택한 태그로 노트 재탐색

소유자는 선택한 태그에 해당하는 노트를 찾아 열 수 있어야 한다. (GOAL-002, EV-001)

- **AC-004:** 서로 다른 태그에만 연결된 두 노트가 있을 때, 한 태그를 선택하면 해당 노트가 결과에 포함되고 일치하지 않는 노트는 포함되지 않는다. 일치 판정은 OD-002에서 정할 규칙을 따른다.
- **AC-005:** 결과에서 노트를 선택하면 그 노트를 열 수 있다. 출처 참조가 첨부된 노트라면 해당 참조도 확인할 수 있다.
- **AC-006:** 선택한 태그에 일치하는 노트가 없으면 결과가 없음을 알리고, 관련 없는 노트를 일치 결과로 제시하지 않는다.
- **AC-007:** 탐색이 실패하면 실패 상태를 알리며, 이를 일치하는 노트가 없는 정상 결과로 표시하지 않는다.

## 제약과 의존성

- 새로운 인증과 팀 공유를 요구하지 않는다. 기존 인증이나 접근 권한 체계가 있다는 뜻은 아니며, 공개 접근 허용도 가정하지 않는다. 개인 소유자 외 접근 시나리오는 입력에 없어 이번 수용 범위에 포함하지 않는다. (DEC-002)
- 노트가 존재하고 다시 열 수 있는 기반이 필요하다. 구현이나 외부 시스템의 존재는 확인되지 않았다. (AS-001)
- 출처 형식, 태그 의미, 삭제 동작, 수치 성능 기준은 아래 미결정 항목으로 유지한다. 미정 값을 기본 정책으로 간주하지 않는다.
- 유효기간이나 원격 데이터 동기화는 입력에 없어 관련 정책 및 오래된 데이터 처리 규칙을 추가하지 않는다.

## 가정과 미결정 사항

### 가정

| ID | 가정과 이유 | 영향 및 확인 방법 |
| --- | --- | --- |
| AS-001 | 입력이 노트에 대한 동작을 요구하므로 시나리오 시작 시 기존 노트가 있다고 가정한다. | 노트 생성·유입 요구는 정의되지 않았다. 구현 범위 확정 시 노트를 어떻게 확보하는지 확인하고, 별도 기능이 필요하면 요구를 추가한다. |
| AS-002 | 선택한 태그로 찾으려면 노트와 태그의 연결이 필요하므로 소유자가 연결할 수 있다고 가정한다. | FR-002가 이 가정에 의존한다. 태그가 이미 제공되는지, 직접 연결해야 하는지는 OD-002 결정 시 확인한다. |

### 미결정 사항

| ID | 미정 선택 | 범위·동작 영향과 차단 여부 | 재검토 조건 |
| --- | --- | --- | --- |
| OD-001 | 출처 참조의 허용 형식과 노트당 개수 | URL, 텍스트 등 어느 형식도 확정하지 않는다. 문서 검토는 가능하지만 FR-001의 입력 범위 및 AC-001 최종 판정을 차단한다. | 첨부 기능의 구현 범위나 수용 예시를 확정할 때 |
| OD-002 | 태그를 생성·선택·연결하는 방식과 일치 규칙 | 대소문자, 복수 태그 검색, 기존 태그 제공 여부를 임의로 정하지 않는다. FR-002 및 FR-003의 세부 동작과 AC-003·AC-004 최종 판정을 차단한다. | 태그 기능의 구현 범위와 검색 예시를 확정할 때 |
| OD-003 | 삭제 대상과 삭제 동작 | SRC-001에 명시적으로 미정이다. 삭제 관련 요구는 보류한다. 삭제 구현은 차단하지만 삭제를 사용하지 않는 첨부·탐색 시나리오의 검토는 차단하지 않는다. | 노트·참조·태그의 삭제 또는 제거를 범위에 넣을 때 |
| OD-004 | 수치 성능 목표 | SRC-001에 명시적으로 미정이다. 정량 성능 합격 판정은 차단하지만 기능 결과의 검토는 가능하다. | 성능 수용 기준을 정하거나 실제 사용에서 지연 문제가 확인될 때 |

현재 작업 흐름의 사용성·수요·성과는 검증되지 않았다. 개인용 제안의 검토 자체를 위해 시장 검증을 요구하지 않는다. 향후 사용 관찰을 수행한다면 GOAL-001·GOAL-002의 달성 여부를 확인할 수 있으나, 이는 수행되지 않은 검증 제안이다. (EV-002)

## 변경 이력

- **revision 1:** 직접 입력으로 신규 PRD를 작성했다. 출처 첨부와 태그 재탐색을 GOAL/FR/AC로 구체화하고, 명시적 제외 사항과 미결정 삭제·성능 정책을 보존했다. 노트 존재 및 태그 연결은 가정으로 분리했다. 상위 문제 문서를 생성하지 않았으며 독립 검토나 구현은 수행하지 않았다.
