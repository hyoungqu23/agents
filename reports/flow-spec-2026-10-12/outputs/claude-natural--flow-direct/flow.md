# 개인 독서 노트 — 사용자 흐름 명세

## 범위와 출처

- 입력은 `direct-input.md`(SRC-001)뿐이며 선행 문서(PRD, 문제 프레임, 리뷰)는 없다. FR/AC ID가 없어 아래 소스 앵커를 사용한다.
- 사용자: 본인 한 명(개인 용도). 역할 구분 없음.
- 요청에 따라 질문 없이 작성했다.

### 소스 앵커

| 앵커 | 원문 요지 |
| --- | --- |
| A1 | 기존에 있는 정확한 태그를 선택한다 |
| A2 | 해당 태그에 저장된 노트만 본다 |
| A3 | 노트를 연다 |
| A4 | 빈 결과와 조회 실패는 눈에 띄게 달라야 한다 |
| A5 | 실패 시 다른 태그를 고를 수 있다 |
| A6 | 개인 용도이며 태그와 노트는 존재한다 (전제) |

### 제약 (SRC-001 명시)

- 포함하지 않음: 편집, 공유, 새 인증, 저장소 설계, 속도 목표.
- 화면 구성·컨트롤 형태·API는 정해진 바 없음 → 후속 설계 영역.

## FLOW-01: 태그로 노트 찾아 열기

- 행위자: 본인. 진입 조건: 노트 조회 기능에 들어옴(A6: 태그와 노트가 존재한다는 전제).

| 행동 또는 조건 | 관찰 가능한 결과 | 다음 단계 또는 종료 | 근거 |
| --- | --- | --- | --- |
| 1. 기존 태그 하나를 정확히 선택 | 선택한 태그가 현재 태그로 표시됨 | 2로 | A1 |
| 2. 선택 태그의 노트 조회 성공, 노트 ≥1건 | 그 태그에 저장된 노트만 나열됨(다른 태그 노트는 없음) | 3으로 | A2 |
| 3. 목록에서 노트 하나를 엶 | 해당 노트 내용이 보임 | 종료. 다른 태그를 고르려면 1로 재진입 | A3 |
| 2a. 조회 성공, 노트 0건 (빈 결과) | "노트 없음"임이 분명한 상태. 실패 표시와 구별됨 | 다른 태그 선택(1) 가능 | A4 |
| 2b. 조회 실패 | "조회 실패"임이 분명한 상태. 빈 결과 표시와 구별됨 | 5로 | A4 |
| 5. 실패 후 다른 태그를 선택 | 새 태그로 조회가 시작됨 | 1→2로 | A5 |

### 분기 메모

- 빈 성공(2a)과 실패(2b)는 서로 다른 상태이며, 어느 쪽도 다른 쪽으로 표시되면 안 된다(A4).
- 정확한 태그 선택만 다룬다(A1). 부분 일치·검색·태그 생성은 소스에 없어 다루지 않는다.

## 미결 사항

- 소스가 요구하는 흐름에 차단되는 결정은 없다. 아래는 소스가 정하지 않았고 이 문서도 정하지 않은 항목이다.
  - OD-01: 실패 후 같은 태그 재시도 허용 여부 — 소스는 "다른 태그 선택"만 명시. 재시도 정책은 만들지 않음. 차단 아님.
  - OD-02: 실패 원인 구분(종류별 메시지) 필요 여부 — 소스에 없음. 차단 아님.
  - OD-03: 노트를 연 뒤 목록으로 돌아가는 방식 — 소스에 없음. 후속 설계에서 탐색 가능.

## 상태 사유

`ready_for_review`: 소스가 요구한 모든 결과가 흐름에 매핑되었고 미결 항목은 비차단이다. 독립 리뷰나 게이트 통과가 아니며 구현 승인도 아니다.
