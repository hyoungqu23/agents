# 내부 문서 검토에서 의도한 리비전 열기 — 사용자 흐름 명세

## 1. 범위와 입력

**범위.** 기존 내부 사용자가 검토용 문서를 열 때 전달자가 의도한 리비전을 여는 흐름과, 접근 대상이 아닌 사용자의 차단 흐름. 다루는 요구사항은 FR-001–FR-004, AC-001–AC-004(모두 SRC-001)다.

**역할.**
- 문서 담당자: 검토용 문서를 전달하고 의도한 리비전을 정하는 사람.
- 내부 수신자: 기존 로그인 계정을 가진 내부 동료.
- 비대상 사용자: 익명 사용자 또는 기존 내부 사용자가 아닌 사람.

**유지하는 출처 결정.** DEC-001(기존 내부 사용자만 대상, 익명 공유·새 로그인 구현 범위 밖), DEC-002(만료·복사/내보내기 제한·철회 미정), DEC-003(첫 성공 관찰은 의도한 리비전을 여는지; 개선율 목표 없음), DEC-004/DEC-005(UI·DB 설계 없음, 질문 없이 로컬 입력만 사용).

**입력 상태.** PRD는 `needs_decision`이다. 별도 리뷰나 gate 결과는 제공되지 않았으며, 이 문서는 gate 통과나 구현 승인이 아니다. PRD 내용 해시는 위 frontmatter에 기록했다. 4/12명 수치(EV-002)는 보고된 값이며 독립 검증되지 않았고 기준선도 없다. 이 문서는 이를 목표나 기준선으로 쓰지 않는다.

**이 문서가 정하지 않는 것.** 화면, 전달 수단(링크 여부 포함), API, 저장 구조. 흐름의 "열기"는 전달 수단과 무관한 사용자 행동이다.

## 2. 흐름 목록과 AC 대조

| FLOW | 요약 | 연결 | 차단 결정 |
| --- | --- | --- | --- |
| FLOW-001 | 허용된 내부 수신자가 의도한 리비전을 연다 | FR-001, FR-004 / AC-001, AC-004 | OD-004, OD-005 |
| FLOW-002 | 전달 후 원본 변경 뒤 재접근 | FR-002 / AC-002 | OD-004 |
| FLOW-003 | 수신자가 보관한 과거 PDF를 연다(제품 밖 경로 관찰) | AC-002의 불일치 판정, PRD 시나리오 3 | OD-002 |
| FLOW-004 | 익명·비내부 사용자의 접근 시도 | FR-003 / AC-003 | 없음(차단 안내 방식은 미지정) |
| FLOW-005 | 의도한 리비전을 열지 못함 | PRD 시나리오 5, GOAL-001 | OD-006, OD-001, OD-003 |

**AC 대조.**
- AC-001 → FLOW-001. 기대 리비전과 권한 조건이 OD-004/OD-005에 달려 있어 완전 검증은 보류.
- AC-002 → FLOW-002, FLOW-003. 기대 리비전은 OD-004 이후 확정.
- AC-003 → FLOW-004. 현재 정보로 분기 확정 가능.
- AC-004 → FLOW-001의 로그인 분기. 허용 대상 정의는 OD-005. 새 로그인 체계 구현은 완료 조건이 아니다.
- 만료(OD-001), 복사·내보내기 제한(OD-002), 접근 철회(OD-003)는 PRD에 FR/AC가 없어 전용 흐름을 만들지 않았다. 아래 6절에 영향 지점만 표시한다.
- 빈 문서 취급은 입력에 정의가 없다. 별도 흐름이나 동작을 만들지 않았고 FLOW-005의 미결로만 둔다.

## 3. 흐름

### FLOW-001 — 허용된 내부 수신자가 의도한 리비전을 연다

- **행위자:** 내부 수신자(담당자가 의도한 리비전을 먼저 정해 둔 상태).
- **진입 조건:** 담당자가 검토를 위해 문서를 전달했다. 수신자는 기존 로그인 계정을 가진다. 전달 수단은 미확정.
- **연결:** FR-001, FR-004, AC-001, AC-004, GOAL-001, GOAL-002.

| 행동 또는 조건 | 관찰 가능한 결과 | 다음 단계 또는 종료 | 요구사항 / 결정 |
| --- | --- | --- | --- |
| 1.1 수신자가 문서를 열려 한다 | 기존 계정으로 본인임이 확인되는 상태가 된다. 새 로그인 체계는 도입하지 않는다 | 1.2로 | AC-004, DEC-001 |
| 1.2 해당 문서의 허용 대상이다 | 문서 내용이 열린다 | 1.3으로 | AC-001, AC-004; 허용 대상 규칙은 **OD-005** |
| 내부 사용자지만 해당 문서의 허용 대상이 아니다 | 내용이 열리지 않는다. 허용 대상 판정 규칙, 이때의 안내·결과는 미정 | 종료(규칙은 OD-005 이후) | OD-005; FR-003 참조 |
| 1.3 열린 리비전이 의도한 리비전과 일치한다 | 성공으로 관찰된다 | 종료(검토 진행) | AC-001, DEC-003 |
| 열린 리비전이 의도한 리비전과 다르다 | 성공 기준 미충족으로 관찰·기록된다 | 종료 | AC-001, DEC-003 |
| 의도한 리비전을 열 수 없다 | FLOW-005로 | FLOW-005 | OD-006 |

**미결.** "의도한 리비전"을 누가 언제 어떤 기준으로 정하는지는 OD-004다. 최신 자동 선택이나 전달 시점 고정을 기본값으로 가정하지 않았다. 문서별 허용 대상은 OD-005이며, 내부 사용자라는 사실만으로 모든 문서에 접근 가능하다고 보지 않는다.

### FLOW-002 — 전달 후 원본 변경 뒤 재접근

- **행위자:** 내부 수신자(이전에 문서를 연 적이 있거나 전달받은 상태).
- **진입 조건:** 전달 이후 원본이 변경되었고 수신자가 다시 문서를 연다.
- **연결:** FR-002, AC-002, EV-001, EV-002, GOAL-001.

| 행동 또는 조건 | 관찰 가능한 결과 | 다음 단계 또는 종료 | 요구사항 / 결정 |
| --- | --- | --- | --- |
| 수신자가 원본 변경 후 문서를 다시 연다 | FLOW-001과 같은 접근 확인을 거친다 | FLOW-001 1.1–1.2 | AC-002 |
| 이 상황에서의 의도한 리비전이 **정해져 있다** | 열린 리비전과 그 기준을 대조한다 | 아래 두 행 | OD-004 |
| 열린 리비전 = 합의된 의도한 리비전 | 성공으로 관찰된다 | 종료 | AC-002 |
| 열린 리비전 ≠ 합의된 의도한 리비전(예: 과거 파일이 열림) | 성공으로 판정하지 않는다 | 종료, 불일치 경로 기록 대상 | AC-002 |
| 의도한 리비전의 기준이 **정해지지 않음** | 분기별 기대 결과를 지정하지 않는다 | 보류 | **OD-004** |

**분기점과 영향.** OD-004의 결과에 따라 같은 재접근이 서로 다른 기대 결과를 가질 수 있다. 가능한 방향(최신 / 전달 시점 / 담당자의 그때그때 지정)은 제안이 아니라 비교 대상이며 어느 것도 채택하지 않았다.

### FLOW-003 — 수신자가 보관한 과거 PDF를 연다

- **행위자:** 내부 수신자.
- **진입 조건:** 수신자가 이전 내보내기 PDF를 보관 중이고, 원본이 이후 변경되었다.
- **연결:** AC-002(불일치 시 성공 아님), PRD 시나리오 3, EV-001, EV-003.
- **성격:** 제품 밖에서 열리는 파일이므로 현재는 관찰·대조 흐름이다. 제품이 이를 통제한다는 요구는 없다.

| 행동 또는 조건 | 관찰 가능한 결과 | 다음 단계 또는 종료 | 요구사항 / 결정 |
| --- | --- | --- | --- |
| 수신자가 보관된 PDF를 연다 | 열린 리비전을 의도한 리비전과 대조할 수 있다 | 아래 두 행 | PRD 시나리오 3 |
| 일치 | 성공 관찰 | 종료 | DEC-003 |
| 불일치 | 성공 아님. 어떤 파일·전달 경로로 열었는지 함께 기록하는 것이 제안된 관찰 방법이다(측정 기능 요구 아님) | 종료 | AC-002, DEC-003 |
| 보관 PDF를 자동 갱신·삭제·차단해야 하는가 | 정해지지 않음. 해당 동작을 만들지 않는다 | 보류 | **OD-002**, DEC-002 |

### FLOW-004 — 익명·비내부 사용자의 접근 시도

- **행위자:** 비대상 사용자(익명 또는 기존 내부 사용자가 아님).
- **진입 조건:** 이번 기능으로 문서 접근을 시도한다.
- **연결:** FR-003, AC-003, DEC-001, GOAL-002.

| 행동 또는 조건 | 관찰 가능한 결과 | 다음 단계 또는 종료 | 요구사항 / 결정 |
| --- | --- | --- | --- |
| 비대상 사용자가 접근을 시도한다 | 문서 내용이 열리지 않는다. 차단 안내 방식은 지정하지 않는다 | 종료 | AC-003, DEC-001 |
| 비대상 사용자가 계정을 만들거나 익명 공유로 우회하려 한다 | 이번 범위에서 지원하지 않는다 | 종료 | DEC-001(새 로그인·익명 공유 범위 밖) |

내부 사용자이지만 해당 문서의 허용 대상이 아닌 경우는 FLOW-001의 OD-005 분기이며, 이 흐름에 포함하지 않는다.

### FLOW-005 — 의도한 리비전을 열지 못함

- **행위자:** 내부 수신자.
- **진입 조건:** 접근은 허용되었지만 의도한 리비전이 이용 불가이거나 열기에 실패한다.
- **연결:** PRD 시나리오 5, GOAL-001. 이 흐름에 대응하는 AC는 아직 없다.

| 행동 또는 조건 | 관찰 가능한 결과 | 다음 단계 또는 종료 | 요구사항 / 결정 |
| --- | --- | --- | --- |
| 의도한 리비전이 열리지 않는다 | 성공 기준 미충족. 실패 안내의 내용과 방식은 미정 | 재시도 여부는 미정 | **OD-006** |
| 다른 리비전이 대신 제공될 수 있는가 | 정해지지 않음. 대체본이 열려도 성공으로 간주하지 않는다 | 보류 | **OD-006**, GOAL-001 |
| 접근 기간 만료 또는 철회로 열리지 않는다 | 해당 정책이 없어 동작 미정 | 보류 | **OD-001**, **OD-003** |
| 열려는 콘텐츠가 비어 있다 | 입력에 정의 없음. 실패와 "빈 성공"의 구분도 미정 | 보류 | OD-006 |

재시도 정책, 오류 목록, 권한 체계는 입력에 없어 만들지 않았다.

## 5. 열린 결정과 영향

| ID | 영향받는 흐름·분기 | 지금 가능한 작업 |
| --- | --- | --- |
| OD-001 | FLOW-005 만료 분기 | 링크 접근을 쓰기로 정하기 전까지 보류 |
| OD-002 | FLOW-003 사본 통제 분기 | 불일치 관찰·대조만 가능 |
| OD-003 | FLOW-005 철회 분기 | 보류 |
| OD-004 | FLOW-001, FLOW-002 기대 리비전 | 분기 구조 탐색은 가능, 기대 결과 확정은 불가 |
| OD-005 | FLOW-001 허용·거부 분기 | 비대상 차단(FLOW-004)은 진행 가능 |
| OD-006 | FLOW-005 전체 | 실패가 성공이 아니라는 원칙만 확정 |

OD 원문, 차단 범위, 재논의 조건은 SRC-001 7절을 따른다. 이 문서에서 바꾸거나 기본값을 고르지 않았다.

## 6. 디자인 핸들오프

- **탐색 가능:** 허용·비허용·불일치·실패 상태를 사용자가 구분할 수 있게 하는 방식, 전달 수단 비교. 시각 형태는 선택하지 않았다.
- **제품 결정이 필요:** OD-004(기대 리비전), OD-005(허용 대상), OD-006(실패·대체본), 그리고 정책 OD-001–OD-003.
- **제약:** DEC-001(기존 내부 사용자만, 새 로그인·익명 공유 없음), DEC-003(성공 = 의도한 리비전 열림), DEC-004/DEC-005(UI·DB 제안 없음).
- 이 문서는 디자인·프로토타입·구현·commit·게시를 포함하지 않는다.

## 7. 성숙도와 변경 이력

`needs_decision`: AC-003은 흐름으로 확정 가능하지만, 핵심 AC-001·AC-002는 OD-004/OD-005에 달려 있고 실패·정책 분기(OD-001–OD-003, OD-006)가 남아 있다. 질문 없이 로컬 입력(prd.md, problem.md, observed-notes.md)만으로 작성했고 외부 조회는 하지 않았다. 이는 독립 검토나 gate 통과, 구현 승인이 아니며, 수요·효과·기술 실현 가능성을 뜻하지도 않는다.
