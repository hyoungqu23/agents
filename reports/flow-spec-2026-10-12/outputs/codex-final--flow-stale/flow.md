# Personal tag finder 사용자 흐름 명세

## 범위와 근거

사용자는 기존 읽기 노트를 사용하는 개인 소유자다. 목표는 기존 태그를 정확히 선택하여 해당 태그가 붙은 노트를 찾고 저장된 내용을 여는 것이다(SRC-001, EV-001·GOAL-001; SRC-003).

SRC-001의 DEC-001을 그대로 적용한다. 노트와 태그는 이미 존재하며, 개인 사용만 다룬다. 태그 편집, 공유, 새 인증, UI 배치, 저장소 설계, 정량적 속도 목표는 범위 밖이다. 태그 선택 방식이나 결과 표시의 시각적 형태는 이 문서에서 정하지 않는다.

SRC-001의 AS-001(제공된 노트·태그를 읽을 수 있다는 가정)은 미검증 상태로 유지한다. 통합 시 실제 자료를 읽을 수 있는지 확인해야 하지만, 선택·열기·빈 결과·실패·재시도 흐름을 검토하는 데에는 비차단이다. 이 가정을 사용자 결정이나 검증된 사실로 취급하지 않는다.

## 이전 리뷰의 유효성

SRC-002의 대상 경로·ID·revision은 현재 PRD와 일치한다. 그러나 리뷰에 기록된 SHA-256 `b231647a9431f958b549ddd96a672c83baad0e9ecf2460a3e40679213a373334`는 현재 SRC-001의 해시와 다르다. 따라서 리뷰는 **stale**이며, `ready_for_flow` 판정을 현재 내용에 승계하지 않는다. 리뷰 자체도 이전 내용에 대한 보고서라는 한계를 명시한다.

리뷰의 `sources`는 빈 배열이므로 당시 의존 자료의 내용 일치 여부는 **unverified**다. 현재 PRD가 참조한 clean-source.md는 직접 읽었으나 과거 리뷰가 같은 내용을 검토했는지는 확인할 수 없다. 이전 PRD 본문이 없어 정확한 변경 차이는 확정하지 않는다. 현재 FR-003·AC-004를 포함한 실제 입력 전체를 기준으로 작성하며, 별도 게이트를 재실행하지 않았다.

## FLOW-001 — 정확한 태그로 찾고 노트 열기

행위자: 개인 사용자. 진입 조건: 기존 태그를 선택할 수 있는 상태. 연결: GOAL-001, FR-001, AC-001.

| 동작 또는 조건 | 사용자가 확인하는 결과 | 다음 단계 또는 종료 | 근거 |
| --- | --- | --- | --- |
| 사용자가 기존 태그 T를 선택한다 | 조회 성공 시 T가 정확히 붙은 노트만 결과로 확인한다 | 결과가 있으면 노트 열기, 없으면 FLOW-002; 조회 실패 시 FLOW-003 | FR-001, FR-002 |
| N1에는 alpha, N2에는 beta가 있고 사용자가 alpha를 선택한다 | N1이 결과에 포함되고 N2는 포함되지 않는다 | N1 열기 | AC-001 |
| 사용자가 결과의 N1을 연다 | N1에 저장된 노트 내용이 보인다 | 찾기·열기 목표 달성으로 종료 | AC-001 |

노트 열기 자체의 실패 동작은 원문에서 정의하지 않았다. 조회 실패와 동일한 정책을 임의로 적용하지 않으며, 별도 오류 정책은 이 범위의 요구사항으로 추가하지 않는다.

## FLOW-002 — 성공한 조회의 빈 결과 확인

행위자: 개인 사용자. 진입 조건: FLOW-001 또는 FLOW-003의 조회가 성공했지만 선택 태그에 연결된 노트가 없음. 연결: FR-002, AC-002.

| 동작 또는 조건 | 사용자가 확인하는 결과 | 다음 단계 또는 종료 | 근거 |
| --- | --- | --- | --- |
| 선택 태그의 조회가 성공하고 일치 노트가 0개다 | 조회 실패가 아니라 해당 태그에 노트가 없다는 식별 가능한 빈 결과를 확인한다 | 빈 결과 확인으로 종료; 다른 기존 태그를 선택하면 FLOW-001에 재진입 | AC-002, FR-001 |

빈 결과에는 실패에 대한 재시도 규칙을 적용하지 않는다. 빈 결과 메시지의 문구와 시각적 표현은 후속 디자인에서 정한다.

## FLOW-003 — 조회 실패 확인과 명시적 재시도

행위자: 개인 사용자. 진입 조건: 선택한 태그 T에 대한 조회가 실패함. 연결: FR-002, FR-003, AC-003, AC-004.

| 동작 또는 조건 | 사용자가 확인하는 결과 | 다음 단계 또는 종료 | 근거 |
| --- | --- | --- | --- |
| T의 조회가 실패한다 | 성공한 빈 결과와 구별되는 조회 실패를 확인한다. 선택 태그 T는 유지된다 | 실패 상태에서 사용자 동작을 기다림 | AC-003, FR-003 |
| 사용자가 재시도를 명시적으로 실행하지 않는다 | 실패 상태에서 자동 재시도가 발생하지 않는다 | 그대로 종료하거나 사용자 동작을 기다림 | AC-004 |
| 사용자가 재시도를 명시적으로 실행한다 | 유지된 동일 태그 T로 다시 조회한다 | 성공하고 결과가 있으면 FLOW-001의 결과·열기로, 성공하고 0개면 FLOW-002로 이동 | AC-004, AC-001, AC-002 |
| 명시적 재시도도 실패한다 | 실패로 표시하고 T를 계속 유지한다 | 같은 실패 상태로 복귀; 이후 재시도도 명시적 동작이 필요함 | FR-003, AC-003, AC-004 |
| 실패 후 사용자가 다른 기존 태그를 선택한다 | 새로 선택한 태그에 대한 조회 흐름을 시작한다 | FLOW-001에 재진입 | FR-001 |

재시도 횟수 제한, 지연, 자동 복구 정책은 추가하지 않는다. 명시적 재시도를 어떤 시각적 조작 요소로 제공할지는 후속 디자인 범위다.

## 수용 기준 연결과 인계

| 현재 PRD 수용 기준 | 대응 흐름 | 확인할 동작 |
| --- | --- | --- |
| AC-001 | FLOW-001 | alpha 선택 시 N1 포함·N2 제외, N1 열기 시 저장된 내용 표시 |
| AC-002 | FLOW-002 | 성공한 0개 결과를 식별 가능하게 표시 |

모든 범위 내 AC를 연결했다. 상태는 **ready_for_review**다. 선언된 흐름을 막는 미결 제품 정책은 없으며, AS-001의 검증은 통합 시 남아 있다. 후속 디자인은 위 흐름과 DEC-001의 제약을 유지하며 태그 선택, 결과 확인, 내용 열기, 빈 결과·실패 구분, 명시적 재시도 표현을 탐색할 수 있다. 이 문서의 완성은 독립 리뷰 통과, 구현 승인 또는 기존 리뷰의 갱신을 의미하지 않는다.
