# 내부 문서 검토에서 의도한 리비전 열기 — 사용자 흐름 명세

## 범위와 출처 해석

문서 담당자가 검토를 위해 전달한 문서를 기존 내부 수신자가 열고, 실제 열린 리비전이 의도한 리비전과 일치하는 결과를 다룬다. 담당자는 전달 맥락의 주체이며, 리비전 기준을 언제 누가 정하는지는 OD-004로 남긴다. GOAL-001·GOAL-002, FR-001–FR-004 및 AC-001–AC-004 전체가 범위다. [SRC-003 §2–5]

EV·DEC·OD 식별자는 상위 문서의 의미를 유지한다. 이 문서의 SRC-003은 PRD 파일을 가리키며, PRD 내부 SRC-003(당시 사용자 요청)과 다르다.

| 유지하는 근거·결정 | 흐름에 적용하는 의미 |
| --- | --- |
| EV-000–EV-002 | 합성 메모에는 주간 PDF 전달, 검토 후 원본 변경, 과거 파일 보관 가능성과 지난주 **12명 중 4명**의 오래된 버전 열기가 보고되어 있다. 독립 검증이나 과거 기준선은 없으며 반복 빈도·개선율·경제적 효과로 확장하지 않는다. [SRC-001 서두 및 User-provided context] |
| EV-003 | 현재 우회책은 PDF 파일명의 리비전 표시와 교체 첨부파일 전달이다. 기존 로그인 계정이 있지만 문서 권한은 별도 미결정이다. [SRC-001 Current workaround] |
| DEC-001 | 기존 내부 사용자만 대상이다. 익명 공유와 새 로그인 구현은 범위 밖이다. 기존 계정 사용 조건을 보존하되 로그인 화면·절차를 새로 정하지 않는다. |
| DEC-002 | 만료, 복사·내보내기 제한, 철회는 유보된 정책이다. 허용·금지 또는 무기한 접근을 기본값으로 두지 않는다. |
| DEC-003 | 첫 성공 관찰은 의도한 리비전과 실제 열린 리비전의 일치다. 제품 내 리비전 표시·자동 판정·분석 수집 기능을 뜻하지 않는다. |
| DEC-004·DEC-005 | 각각 문제 정의와 PRD 작성 당시의 산출물 범위다. 현재 요청은 flow.md 작성으로, 과거 원자료의 산출물 지시가 현재 요청을 대체하지 않는다. UI·데이터베이스 설계는 추가하지 않는다. |
| DEC-006 | 이번 요청에 따라 질문 없이 제공된 로컬 자료만으로 flow.md를 작성한다. 외부 조회·설치·commit·게시를 하지 않는다. [SRC-004] |

링크는 확정된 전달 수단이 아니다. 아래의 ‘문서 열기’는 특정 링크, 목록, 버튼 또는 새 공유 기능을 전제하지 않는다. 화면 배치, API, 저장 구조, 출시 일정은 정하지 않는다. 별도 AS는 채택하지 않았으며, 조건부 경로는 합의된 정책으로 간주하지 않는다.

기존 flow.md 및 독립 검토 보고서는 제공되지 않았다. 세 원자료의 실제 내용을 읽었고, 결정 간 충돌은 발견하지 않았다. problem.md의 `ready_for_review`는 문제 정의의 상태이며 검토 통과가 아니다. PRD의 미결정을 유지하며, 위 digest는 이번에 읽은 파일의 내용 식별자일 뿐 별도 검토나 최신성 보증이 아니다.

## FLOW-001 — 허용된 내부 수신자의 문서 열기

**행위자:** 기존 내부 수신자. **진입:** 담당자가 검토 문서를 전달한 상황에서 수신자가 문서를 열려 한다. 성공 경로의 전제는 의도한 리비전과 문서 접근 허용 조건이 정해져 있다는 것이다. 이는 OD-004·OD-005가 이미 해결됐다는 선언이 아니다. **연결:** FR-001·FR-004, AC-001·AC-004, DEC-001·DEC-003.

| 행동 또는 조건 | 사용자가 관찰하는 결과 | 다음 단계 또는 종료 | 연결 |
| --- | --- | --- | --- |
| 수신자가 기존 로그인 계정을 이용하는 조건에서 문서 열기를 시도한다. | 접근 결과에 따라 문서를 열 수 있거나 열 수 없다. 계정 존재만으로 허용을 확정하지 않는다. | 허용 조건이 확정되고 충족되면 다음 단계, 사용자 범위·권한 분기는 FLOW-004. | AC-004, OD-005 |
| 허용 대상이며 의도한 리비전을 이용할 수 있다. | 의도한 리비전의 문서 내용이 열린다. | 문서를 검토하며 종료. 실제 리비전 일치를 성공 관찰로 대조한다. | AC-001·AC-004 |
| 의도한 리비전이 열리지 않거나 이용할 수 없다. | 기대한 문서를 열지 못한다. | FLOW-005. | OD-006 |
| 전달 이후 원본이 변경된 상태에서 다시 연다. | 변경 후 기준에 따라 열기 결과가 달라질 수 있다. | FLOW-002. | AC-002, OD-004 |

담당자의 리비전 선택 조작이나 수신자의 확인 조작은 입력에 없으므로 만들지 않는다. 성공 대조는 PRD의 관찰 제안이며 제품에 판정 화면을 요구하지 않는다.

## FLOW-002 — 원본 변경 후 재접근

**행위자:** 다시 검토하려는 기존 내부 수신자. **진입:** 문서 전달 후 원본이 변경되었고 수신자가 다시 열기를 시도한다. **연결:** FR-002, AC-002, EV-001·EV-002, OD-004·OD-005.

| 행동 또는 조건 | 사용자가 관찰하는 결과 | 다음 단계 또는 종료 | 연결 |
| --- | --- | --- | --- |
| 수신자가 변경 이후 문서를 다시 연다. | 열릴 리비전은 합의된 기준에 따라야 한다. 아직 어떤 리비전인지 확정할 수 없다. | OD-004에서 기준·시점·주체를 정한 후 다음 분기를 확정한다. | AC-002, OD-004 |
| 합의된 의도한 리비전이 열리고 접근도 허용된다. | 해당 리비전의 내용을 검토할 수 있다. | 실제 열린 리비전과 기대 리비전이 일치하면 성공 종료. | AC-002, OD-005 |
| 다른 리비전이 열린다. | 수신자가 보는 내용이 기대 리비전과 다르다. 자동 경고 여부는 정해지지 않았다. | 불일치로 관찰하며 성공으로 종료하지 않는다. 과거 PDF였다면 FLOW-003, 복구 결과는 FLOW-005의 미결정에 연결한다. | AC-002, OD-006 |
| 접근 조건에 걸리거나 의도한 리비전을 이용할 수 없다. | 문서를 열지 못하거나 의도한 내용을 얻지 못한다. | 각각 FLOW-004 또는 FLOW-005. | OD-001·OD-003·OD-005·OD-006 |

최신 리비전 자동 선택과 전달 시점 리비전 고정은 OD-004에서 검토할 수 있는 대안일 뿐 채택된 규칙이 아니다. 기준 결정 전에는 AC-002의 기대 결과를 특정 리비전으로 작성할 수 없다.

## FLOW-003 — 보관한 과거 PDF로 검토

**행위자:** 과거 내보내기 파일을 보관한 내부 수신자. **진입:** 수신자가 이전 PDF를 연다. **연결:** SRC-003 §4 시나리오 3, AC-002의 과거 파일 불일치 조건, EV-003, OD-002. 이 흐름은 기존 이용 경로의 관찰이며 새 제품의 사본 통제 기능이 아니다.

| 행동 또는 조건 | 사용자가 관찰하는 결과 | 다음 단계 또는 종료 | 연결 |
| --- | --- | --- | --- |
| 수신자가 보관한 PDF를 연다. | 그 사본의 내용을 보게 된다. 현재 우회책에서는 파일명에 리비전 표시가 있다. | 해당 검토의 의도한 리비전과 실제 연 리비전을 대조한다. | EV-003, DEC-003 |
| 열린 사본과 의도한 리비전이 다르다. | 오래된 사본으로 검토한 불일치가 관찰된다. 제품이 이를 탐지·안내한다고 가정하지 않는다. | 성공으로 판정하지 않는다. 어떤 파일·전달 경로를 사용했는지 확인하는 관찰을 제안한다. 자동 교체·삭제·차단은 확정하지 않는다. | AC-002, OD-002 |
| 사본이 의도한 리비전과 일치한다. | 이번 열기에서는 의도한 내용을 볼 수 있다. | 이번 리비전 일치 관찰로 종료. 이후 변경에도 일치하거나 새 접근 기능이 성공했다는 증거는 아니다. | DEC-003 |
| 수신자가 현재 문서 접근 경로로 다시 열기를 시도한다. | 허용 조건과 리비전 기준에 따른 결과를 보게 된다. | FLOW-002로 재진입. 전환 수단·자동 유도는 미정이다. | OD-004·OD-005 |

교체 첨부파일 재전달은 현재 우회책의 기록이며 새 기능의 필수 복구 절차로 승격하지 않는다. 복사·내보내기 실행 자체의 허용 여부 및 결과는 OD-002 결정 전까지 명세할 수 없다.

## FLOW-004 — 사용자 범위 및 접근 정책 분기

**행위자:** 이번 기능으로 접근을 시도하는 사용자. **진입:** 문서 열기 또는 재접근 시도. **연결:** FR-003, AC-003 및 AC-001·AC-004의 권한 전제, DEC-001·DEC-002.

| 행동 또는 조건 | 사용자가 관찰하는 결과 | 다음 단계 또는 종료 | 연결 |
| --- | --- | --- | --- |
| 익명 사용자 또는 기존 내부 사용자에 해당하지 않는 사용자가 접근한다. | 이번 기능으로 문서 내용을 열 수 없다. 차단 문구·안내 방식은 지정하지 않는다. | 내용 접근 없이 종료. 가입·새 로그인·권한 요청 경로를 추가하지 않는다. | AC-003 |
| 기존 내부 사용자가 접근한다. | 기존 계정만으로 문서 접근 결과를 단정할 수 없다. | OD-005로 허용 여부를 결정한 사례에서만 허용 경로를 FLOW-001 또는 FLOW-002로 연결한다. 내부 거부 판정·결과·안내의 구체화는 유보한다. | AC-001·AC-004, OD-005 |
| 링크 접근을 채택하고 만료 조건을 다룬다. | 기간 경과 후 열 수 있는지와 보이는 결과가 미정이다. | OD-001 결정 전 해당 분기 확정 보류. 갱신·재발급 동작도 만들지 않는다. | OD-001 |
| 접근 철회 이후 다시 접근하거나 기존 접근을 계속한다. | 어떤 접근이 가능하고 어떤 결과를 보게 되는지 미정이다. | OD-003 결정 전 철회 이후 경로 확정 보류. 열린 문서·보관 사본의 처리도 추정하지 않는다. | OD-003, 사본은 OD-002 |

익명·외부 접근 차단은 이번 기능의 범위다. 이미 전달된 PDF를 회수하거나 외부에서 열지 못하게 통제한다는 의미로 확장하지 않는다.

## FLOW-005 — 의도한 리비전 이용 불가 또는 열기 실패

**행위자:** 문서를 열려는 내부 수신자. **진입:** FLOW-001·FLOW-002에서 의도한 리비전을 얻지 못한 경우. **연결:** SRC-003 §4 시나리오 5, FR-001·FR-002의 성공 경계, OD-006. 구체 실패 동작에 대한 FR/AC는 아직 없다.

| 행동 또는 조건 | 사용자가 관찰하는 결과 | 다음 단계 또는 종료 | 연결 |
| --- | --- | --- | --- |
| 의도한 리비전이 이용 불가하거나 열기 작업이 실패한다. | 의도한 리비전의 내용을 볼 수 없다. 오류 표현 방식은 미정이다. | 성공 미충족으로 기록한다. 종료 안내와 복구 동작은 OD-006 결정 대기다. | OD-006, AC-001·AC-002 |
| 다른 리비전으로 대체하는 처리를 검토한다. | 대체본 제공 여부와 안내는 미정이며, 의도와 다른 대체본은 성공으로 간주할 수 없다. | OD-006 결정 전 자동 대체하지 않는다는 정책조차 새로 확정하지 않는다. 제공·차단 어느 결과도 유보한다. | OD-006, DEC-003 |
| 재시도 또는 취소 경로를 구체화하려 한다. | 재시도 제공 여부·횟수·자동 실행·취소 결과는 입력에 없다. | 동작을 추가하지 않는다. 다시 열기가 허용되는 복구안을 채택할 경우 FLOW-001 또는 FLOW-002로 돌아갈 수 있으나 현재는 제안에 그친다. | OD-006 |

빈 콘텐츠의 정상 열기와 열기 작업 실패는 다른 조건이다. 입력은 빈 문서 취급을 정의하지 않았으므로 빈 결과를 오류 또는 성공으로 판정하지 않으며, 빈 상태 UI나 검색 결과 없음 흐름도 만들지 않는다. [SRC-003 §5·§7, OD-006]

| AC-002 / FR-002 | FLOW-002, FLOW-003, FLOW-005 | 변경 후 일치와 과거 파일 불일치를 구분했다. OD-004 결정 전 특정 기대 리비전과 전체 경로 검증을 확정할 수 없다. |
| AC-003 / FR-003 | FLOW-004 | 익명·비내부 사용자는 이번 기능으로 내용을 열 수 없다는 결과를 명세했다. 차단 안내 형식은 요구하지 않는다. |
| AC-004 / FR-004 | FLOW-001, FLOW-004 | 기존 계정을 이용하는 허용 대상의 문서 열기를 정의했다. 허용 대상 판정은 OD-005에 달려 있다. 새 로그인 구현 불요는 흐름 전반의 제약이며 별도 상호작용을 만들지 않는다. |

모든 범위 내 AC를 흐름에 연결했으나, 연결은 수용 기준 검증 완료를 뜻하지 않는다. 만료·사본·철회·실패의 세부 AC는 PRD에서도 미작성 상태이며 여기서 새 상위 AC를 발명하지 않는다.

## 성숙도와 변경 이력

`needs_decision`: 사용자 행동과 결과 및 전체 AC 연결은 초안으로 작성했으나 리비전 기준·문서 권한과 정책 경계가 열려 있다. 질문 없이 가능한 범위를 기록했다. 원자료의 합성 관찰 외에 실제 수요·해결 효과·기술 실현 가능성을 검증하지 않았으며, 이 문서는 독립 검토 통과나 구현 승인이 아니다.
