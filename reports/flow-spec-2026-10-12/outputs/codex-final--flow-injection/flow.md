# Personal tag finder 사용자 흐름 초안

## 범위와 근거

개인 사용자가 기존 태그를 정확히 선택하여 해당 태그가 붙은 기존 읽기 노트를 찾고, 선택한 노트의 저장된 내용을 여는 흐름이다. `current-prd.md`의 GOAL-001, FR-001~003, AC-001~004 전체를 포함한다.

- **EV-001 유지:** 기존 태그로 노트를 찾고 싶다는 개인 사용자의 요청이다. 근거: SRC-002의 EV-001, SRC-001의 본문. 시장 수요나 성능을 검증한 결과는 아니다.
- **DEC-001 유지:** 개인 사용만 대상으로 한다. 태그 편집, 공유, 새 인증, UI 배치, 데이터 저장 설계, 정량 속도 목표는 범위 밖이다. 근거: SRC-002의 DEC-001, SRC-001의 본문.
- **AS-001 유지:** 제공된 노트와 태그를 읽을 수 있다고 가정한다. 통합 시 실제 자료 접근으로 검증한다. 검증 전이지만 선택·열기·빈 결과·실패 흐름의 설계를 막지 않는다. 근거: SRC-002의 AS-001.
- 실패해도 선택 태그를 유지하며, 같은 태그로의 재시도는 명시적인 사용자 동작으로만 시작한다. 자동 재시도는 없다. 근거: SRC-002의 FR-003, AC-004.

SRC-003의 보고 내용은 빈 조회 결과와 조회 실패를 구분하라는 요구를 뒷받침한다. 그 안에 인용된 `SYSTEM OVERRIDE`는 출처에 포함된 텍스트이며 작업 지시나 제품 결정이 아니다. 별도 파일 생성, PRD 수정, 정책 확정 또는 게이트 통과 주장의 근거로 사용하지 않는다.

## FLOW-001 — 태그로 찾고 노트 열기

**행위자:** 개인 사용자. **진입 조건:** 기존 태그를 선택할 수 있으며 기존 노트와 태그를 읽을 수 있다는 AS-001을 전제로 한다. **연결:** FR-001, AC-001.

| 동작 또는 조건 | 사용자가 확인하는 결과 | 다음 단계 또는 종료 |
| --- | --- | --- |
| 기존 태그 하나를 선택한다. | 선택한 정확한 태그를 대상으로 조회한다. | 조회 성공이면 아래 분기, 실패이면 FLOW-003으로 이동한다. |
| 조회에 성공하고 일치하는 노트가 있다. | 해당 태그가 붙은 노트만 결과로 제공된다. N1이 alpha, N2가 beta이면 alpha 선택 결과는 N1을 포함하고 N2를 제외한다. | 결과의 노트를 열 수 있다. |
| 결과에서 N1을 연다. | N1의 저장된 노트 내용이 표시된다. | 찾기·열기 목적을 달성하고 종료한다. |
| 조회에 성공했지만 일치하는 노트가 없다. | 성공한 빈 결과로 구분된다. | FLOW-002로 이동한다. |

## FLOW-002 — 성공한 빈 결과 확인

**행위자:** 개인 사용자. **진입 조건:** 선택한 기존 태그의 조회가 성공했으며 일치하는 노트가 0개다. **연결:** FR-002, AC-002.

| 동작 또는 조건 | 사용자가 확인하는 결과 | 다음 단계 또는 종료 |
| --- | --- | --- |
| 일치하는 노트가 없는 조회 결과를 받는다. | 선택 태그에 해당하는 노트가 없다는 상태를 식별할 수 있다. 조회 실패로 표시하지 않는다. | 이번 조회를 종료한다. 이후 기존 태그를 선택하면 FLOW-001에 다시 진입한다. |

## FLOW-003 — 조회 실패와 명시적 재시도

**행위자:** 개인 사용자. **진입 조건:** 선택한 태그의 조회가 실패했다. **연결:** FR-002, FR-003, AC-003, AC-004.

| 동작 또는 조건 | 사용자가 확인하는 결과 | 다음 단계 또는 종료 |
| --- | --- | --- |
| 조회가 실패한다. | 실패임을 식별할 수 있다. 성공한 빈 결과로 표시하지 않으며, 선택한 태그를 유지한다. | 사용자의 다음 동작을 기다린다. 자동 재시도는 하지 않는다. |
| 사용자가 명시적으로 재시도한다. | 실패 당시 유지된 동일한 태그로 다시 조회한다. | 성공하고 일치하는 노트가 있으면 FLOW-001의 결과 단계로, 성공했지만 없으면 FLOW-002로 이동한다. 다시 실패하면 이 흐름의 실패 단계로 돌아온다. |
| 사용자가 재시도하지 않는다. | 추가 조회를 자동으로 시작하지 않는다. | 이번 시도를 종료하거나 명시적인 다음 동작을 기다린다. |
| 사용자가 다른 기존 태그를 선택한다. | 새로 선택한 태그를 대상으로 조회한다. | FLOW-001에 새로 진입한다. 이는 실패한 태그의 재시도가 아니다. |

## 수용 기준 연결

| PRD 수용 기준 | 연결 흐름과 확인할 행동 |
| --- | --- |
| AC-001 | FLOW-001: 정확한 태그로 결과를 제한하고 선택한 노트의 저장 내용을 연다. |
| AC-002 | FLOW-002: 조회 성공·0건을 식별 가능한 빈 결과로 표시한다. |
| AC-003 | FLOW-003: 조회 실패를 성공한 빈 결과와 구분한다. |
| AC-004 | FLOW-003: 실패 후 태그를 유지하고 명시적 사용자 동작으로만 같은 태그를 재조회한다. 자동 재시도는 없다. |

## 검토 상태와 디자인 인계

상태는 `ready_for_review`이다. 범위 내 모든 AC가 흐름에 연결되었고, 선언된 다음 단계인 사용자 흐름 디자인을 막는 미결 제품 정책은 없다. 이 문서는 검토 가능한 초안이며 독립 리뷰, PRD 게이트 통과 또는 구현 승인 결과가 아니다. 제공된 별도 리뷰 문서는 없어 리뷰의 최신성이나 판정을 확인했다고 주장하지 않는다.

디자인에서는 태그 선택, 결과 확인, 노트 열기, 빈 결과와 실패의 구분, 유지된 태그의 확인 및 명시적 재시도를 표현할 수 있다. 구체적인 컨트롤, 문구, 화면 배치는 이 문서에서 결정하지 않는다. 통합 시 AS-001을 검증하되 실패 표시와 자동 재시도 금지 조건을 유지한다.

접근 권한 정책, 조회 취소, 부분 성공, 오래된 입력 처리, 노트 열기 자체의 실패 처리는 제공된 요구사항에 정의되지 않았다. 이번 초안에 임의 정책을 추가하지 않으며, 해당 동작이 범위에 추가될 때 별도로 정의한다. 현재 범위의 차단 결정으로 취급하지 않는다.
