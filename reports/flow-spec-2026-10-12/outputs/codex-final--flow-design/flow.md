# 기존 태그로 읽기 노트 찾기 — 사용자 흐름

## 범위와 근거

개인 사용자가 기존의 정확한 태그로 기존 노트를 찾고 선택한 노트의 저장된 내용을 읽는다. PRD GOAL-001–003, FR-001–003, AC-001–006 전체가 범위다. 새로운 역할은 없다.

상위 EV-001은 합성 평가 입력이라는 사실, EV-002는 관련 없는 노트를 반복해서 열고 목록을 훑는다는 보고다. 실제 고객 조사·독립 관찰·측정으로 확대하지 않는다. DEC-001의 정확한 태그 관계와 내용 열기, DEC-002의 제외 범위, DEC-003의 빈 결과/실패 구분, DEC-004의 행동 설계 범위, DEC-005의 비차단 통합 가정을 유지한다. 태그 편집·유사 태그 확장·팀 공유·새 인증·정량 속도 목표는 추가하지 않는다.

AS-001: 기존 노트·태그 관계·저장된 내용을 실제로 읽을 수 있는지는 확인하지 않았다. 추후 통합에서 확인하며 이 흐름에는 비차단이다. 현재 미해결 제품 정책 OD는 없다. 권한·동시 변경·재시도 정책을 새로 정하지 않는다. 별도의 검토 결과는 제공되지 않았으므로 기존 gate 판정의 유효성을 주장하지 않는다.

## FLOW-001 — 기존 태그 선택과 변경

행위자: 개인 사용자. 진입: 기존 태그를 선택할 수 있는 상태, 또는 이전 태그의 결과/내용/조회 실패 상태. FR-001, AC-001·002, DEC-001.

| 행동 / 조건 | 관찰 결과 | 다음 단계 / 종료 |
| --- | --- | --- |
| 기존 태그 T를 선택하고 조회 성공, 결과가 있음 | T가 달린 모든 기존 노트만 결과로 제공된다 | 결과 노트 선택 → FLOW-002, 다른 태그 선택 → 이 흐름 재진입 |
| T에서 U로 선택 변경, 조회 성공 | U의 정확한 노트 집합으로 대체된다. T에만 속한 노트가 U 결과로 남지 않는다 | FLOW-002 또는 다시 태그 변경 |
| 조회 성공, 결과 0개 | 선택 태그에 대한 빈 결과 | FLOW-003 |
| 조회 실패 | 선택 태그 조회 실패. 이전 결과를 새 태그 결과로 제시하지 않는다 | FLOW-004 |

태그 변경 시 이전에 읽던 내용을 새 결과의 내용으로 오인시키지 않는다. 지연 중 표시의 시각 형태나 캐시 정책은 지정하지 않는다.

## FLOW-002 — 결과 노트 열기

행위자: 개인 사용자. 진입: FLOW-001의 성공한 비어 있지 않은 결과. FR-002, AC-003·004, DEC-001, AS-001.

| 행동 / 조건 | 관찰 결과 | 다음 단계 / 종료 |
| --- | --- | --- |
| 결과에서 노트 N 선택, 내용 읽기 성공 | N의 저장된 내용이 열리며 N의 정체를 알 수 있다. 다른 노트 내용으로 대체하지 않는다 | 읽기 종료; 결과로 돌아가 다른 노트 선택 또는 FLOW-001 |
| N 선택, 내용 읽기 실패 | N의 내용을 열지 못했음을 확인한다. 성공한 내용이나 태그의 빈 결과로 표시하지 않는다 | 결과로 돌아가 다른 노트 선택 또는 FLOW-001 |

결과로 돌아가는 제어는 탐색을 위한 디자인 제안이다. 실패 시 자동 재시도·횟수·대기 시간은 요구하지 않는다. 실제 취소 정책은 제공되지 않았고 추가하지 않는다.

## FLOW-003 — 성공한 조회의 빈 결과

행위자: 개인 사용자. 진입: 선택한 기존 태그에 대한 조회 성공 및 0개 결과. FR-003, AC-005, DEC-003.

성공한 조회라는 조건에서만 해당 태그의 노트가 없음을 표시한다. 내용 열기 대상은 없다. 사용자는 다른 기존 태그를 선택하여 FLOW-001로 재진입하거나 탐색을 종료한다. 실패와 문구·상태 의미를 구분한다.

## FLOW-004 — 태그 조회 실패

행위자: 개인 사용자. 진입: 기존 태그 조회 작업 실패. FR-003, AC-006, DEC-003.

선택 태그의 조회를 완료하지 못했다고 표시하고 결과 유무는 확정하지 않는다. 실패한 조회에 대한 결과 개수 0 또는 노트 없음 문구를 사용하지 않는다. 해당 실패 상태에서는 새 조회 결과의 노트 열기를 제공하지 않는다. 다른 태그 선택으로 FLOW-001에 재진입하거나 탐색을 종료한다. 실패 원인·권한 정책·재시도 방식은 주어지지 않았으며 확정하지 않는다.

## 수용 조건 연결과 디자인 전달

| AC | FR | 흐름 | 확인할 동작 |
| --- | --- | --- | --- |
| AC-001 | FR-001 | FLOW-001 | 정확한 기존 태그의 전체 집합만 제공 |
| AC-002 | FR-001 | FLOW-001 | T → U 변경 시 U 집합으로 교체 |
| AC-003 | FR-002 | FLOW-002 | 선택 N의 저장된 내용 |
| AC-004 | FR-002 | FLOW-002 실패 분기 | N 내용 열기 실패 |
| AC-005 | FR-003 | FLOW-003 | 성공한 빈 결과 |
| AC-006 | FR-003 | FLOW-004 | 실패와 결과 유무 미확정 |

미연결 AC는 없다. 원자료에 근거가 없는 부분 성공·접근 거부·만료 등의 정책 분기는 만들지 않는다. 현재 흐름은 `ready_for_review`: 범위 내 조건과 목적지가 연결되어 검토 가능하다. 독립 검토, 구현 승인, 실제 통합 성공을 뜻하지 않는다.

시각 구조는 이 흐름의 제품 결정이 아니다. 이번 사용자 요청은 별도로 A/B HTML 탐색과 B 보존을 허용한다. 디자인 단계에서는 A 분할 탐색과 B 단계별 탐색을 제안하며, B 선택의 근거는 이번 요청의 “사용자가 B를 선택한 것으로 명시”이다. 선택 이유는 제공되지 않았다. 샘플 노트와 실패 제어는 로컬 시연용이며 실제 데이터나 확정된 오류 정책이 아니다.
