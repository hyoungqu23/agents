# 완료 항목 숨기기 — FE 개발 명세

- 적용 범위·대상 환경: 전달받은 고정된 읽기 전용 props를 표시하는 작은 로컬 목록. 특정 프레임워크·브라우저 버전은 지정되지 않았다.
- 상태 이유: 네 가지 자기 검토를 완료했고 활성 차단 질문이 없다. 번들 helper에서 구조 valid, gaps 없음, AC 정본 목록 AC-local 한 개를 확인했다. ready는 선언 범위의 문서 준비 상태다.
- 미결 목록: [QUESTIONS.md](./QUESTIONS.md)
- 독립 개발 가능 범위: 이 문서에 선언한 전체 로컬 동작.

## 1. 목표·범위·제약

- **FR-local**: 사용자는 `완료 항목 숨기기` 체크박스로 완료된 항목의 표시 여부를 바꾸고, 현재 보이는 항목 수를 확인한다. 수용 기준의 원래 ID는 **AC-local**이다.
- 포함 범위: 초기 표시, 체크·해제에 따른 필터와 표시 개수 변경, 원래 순서 유지·복구, 새로고침 시 초기화, 실제 키보드 Space 토글과 보이는 focus, 기존 blue 토큰 `--accent` 사용.
- 입력은 아래 배열을 전달받은 읽기 전용 props다. 원본 항목·배열을 변경하지 않는다.

```js
[{id:"a",label:"Alpha",done:false},{id:"b",label:"Beta",done:true},{id:"c",label:"Gamma",done:false}]
```

- 제외 범위와 근거: 서버/API, 권한, 저장, 로딩·오류 단계는 요청 원문 2행에서 없다고 확정했다. 항목 편집·삭제·선택은 3행에서 요청하지 않았으며 추가하지 않는다. 저장소 영속화는 3행에서 제외했다.
- 적용 제약: 텍스트 요청이 확정된 동작 기준이다. 이미지·별도 디자인 파일은 제공되지 않았으므로 이미지 관찰에 근거한 규칙은 없다. 내부 컴포넌트와 상태 관리 방식은 개발자 재량이다.
- 현재 앱의 구현 상태는 조사하지 않았다. 이 문서는 목표 동작을 규정한다.

## 5. API 계약·데이터 매핑·오류 처리

### 5.1 사용자 행동과 API

서버/API는 사용하지 않는다(SRC-001 2행). 첫 진입, 체크·해제, 실제 Space 토글, 새로고침의 목록 상태 결정 모두 이 문서의 로컬 계약을 따른다. method/path/operation·요청 시점·응답 schema·HTTP 성공/실패 매핑은 적용되지 않는다. 브라우저 새로고침 자체의 페이지 전송을 별도 기능 API로 정의하지 않는다.

### 5.2 필드와 FE 표현의 연결

아래는 서버 요청/응답 schema가 아니라 제공된 고정 props의 필드와 표시 관계다. 이 입력의 모든 항목에 아래 세 필드가 존재하고 null은 없다. 일반화된 선택 필드·nullable 계약은 제공되지 않았다.

| 요청/응답·원본 필드 | 타입·required/optional·null·enum | FE 표현/매핑 | 빈 값·미지원 값 처리 | 근거 또는 Q-ID |
| --- | --- | --- | --- | --- |
| props 배열의 순서 | 주어진 순서는 a, b, c. 고정 입력 | 필터 후에도 남은 항목은 이 순서를 유지; 해제 시 전체 원래 순서 복구 | 추가 입력 범위 아님 | SRC-001 2–3행 |
| props[].id | 제공 값은 문자열 a, b, c; 이 입력에서 모두 존재·non-null | 원본 항목 식별. 별도 id 표시 요구 없음 | 추가 입력 범위 아님 | SRC-001 2행 |
| props[].label | 제공 값은 문자열 Alpha, Beta, Gamma; 이 입력에서 모두 존재·non-null | 각 표시 항목의 이름을 그대로 표시 | 추가 입력 범위 아님 | SRC-001 2–3행 |
| props[].done | boolean; a=false, b=true, c=false; 이 입력에서 모두 존재·non-null | 체크 시 true 항목만 숨김. 해제 시 값과 무관하게 모두 표시 | 추가 입력 범위 아님 | SRC-001 2–3행 |
| 로컬 체크 상태와 파생 표시 개수 | 체크 상태는 boolean, 최초 false. 표시 개수는 보이는 항목의 수 | false이면 3, true이면 2; 새로고침 시 false/3 | 저장소 값 읽기·쓰기·복구 정책 없음 | SRC-001 3행 |

### 5.3 오류·회복

별도 서버/API·로딩·오류 단계가 없다는 확정 요구에 따라 오류 응답·오류 화면·재시도 계약은 적용되지 않는다. 표시 필터의 되돌리기는 체크 해제이며, 새로고침하면 초기 해제 상태로 돌아간다. 일반적인 브라우저 장애나 제공되지 않은 입력 변형에 대한 오류 정책은 이 기능 명세에 추가하지 않는다.

### 6.2 명세 검토 결과

| 검토 | 수행 범위·방식 | 결과와 한계 |
| --- | --- | --- |
| 구조·ID·상호 참조 | 자기 검토. 여섯 절, §6.1 AC-local 단일 정본 행, FR-local 보존, 출처 참조, QUESTIONS의 companion 경로·동일 feature ID와 빈 질문 목록을 대조. 번들 spec_check.py를 두 문서에 실행 | helper 결과 structure=valid, gaps=[], active_blockers=[], ac_ids=[AC-local]. 중복·미정의 참조·의도하지 않은 AC 분할을 발견하지 못함. helper는 제한된 구조만 검사하며 의미 정확성을 인증하지 않음 |
| 원자료·권위·판본 대조 | SRC-001 전체 1–5행을 직접 읽고 §2.3의 요구·시각 제약·제외 범위를 역대조하는 자기 검토 | 제공된 텍스트의 확정 권위를 유지함. 외부 출처·원본 앱·토큰 정의는 조사하지 않음. 읽지 않은 연결 자료는 없음 |
| 화면·정책·API·AC 정합성 | 초기 3개 → 체크 2개 → 해제 3개 → 새로고침 3개를 §3–6 사이에서 추적. 키보드·focus·레이블·토큰·읽기 전용·비영속화와 제외 범위를 대조 | 상반된 표시·개수·API 상태 전이를 발견하지 못함. 레이아웃·문구 재량을 새 정책으로 확정하지 않음. 앱 동작 검증은 미수행 |
| AC별 구현 내용 재구성 | 별도 호출 없이 같은 작성자가 SRC-001과 현재 SPEC·QUESTIONS를 함께 참조한 자기 검토. 유일한 AC-local의 사용자·초기 상태·행동·로컬 데이터·결과·되돌리기·새로고침을 단계별 재구성 | 단계마다 항목과 개수를 결정할 수 있고 API 성공/실패는 명시적으로 비적용. 구현을 바꾸는 추가 가정·활성 차단 질문을 발견하지 못함. 독립 독자 검토·실제 키보드/브라우저/코드 검증은 수행하지 않음 |

- 검토 대상: SPEC revision 1, QUESTIONS revision 1, SRC-001 이번 실행 원본 전체. 네 검토는 모두 자기 검토이며 별도 독립 판정이 아니다.
- 준비 판정 이유: 네 가지 자기 검토를 완료했고 활성 차단 질문이 없으며 helper의 제한된 구조 검사를 통과해 선언 범위의 명세를 ready로 판정했다. 별도 독립 독자 검토·구현·실행 검증 완료를 뜻하지 않는다.
- 외부 의존·미확인 범위: 문서 범위에 미확정 API·디자인 계약은 없다. `--accent`의 실제 코드 위치·런타임 색상과 앱 실행 환경은 조사하지 않았다. 이는 지정된 토큰 사용 계약을 바꾸지 않는다.
- 후속 검증: AC-local의 모든 단계를 구현 뒤 실제 앱에서 수행한다. 코드 검토와 실제 키보드 Space·focus 확인이 필요하다. 이 문서 작성이나 ready 판정은 구현 완료·런타임 정상 동작·게시를 증명하거나 승인하지 않는다.
