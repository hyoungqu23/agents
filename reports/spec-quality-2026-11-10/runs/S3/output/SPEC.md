# 거래처 초대 화면 — FE 개발 명세 초안

- 적용 범위·대상 버전/환경: 거래처 초대 화면. 앱·서버·디자인 판본과 대상 실행 환경은 unknown.
- 상태 이유: 초안 작성과 네 가지 자기 검토를 수행했으나 역할, API 계약, UI 및 후속 정책이 미정이다. AC-invite를 완결할 수 없어 blocked로 판정한다.
- 미결 목록: [QUESTIONS.md](./QUESTIONS.md). Q-001은 OD-permission의 기존 보류를 보존한다.
- 부분 개발 가능 범위: 이메일 입력 필요와 초대 요청→결과 확인이라는 경계는 확인했다. 이 범위의 자료 정리와 계약 분리는 독립적으로 가능하나, 확정된 외부 동작으로 구현할 수 있는 완결된 흐름은 아직 없다. 구현은 이번 요청에 포함되지 않는다.

## 1. 목표·범위·제약

- 사용자와 달성 결과: 허용된 역할이 거래처 초대 요청을 보내고 결과를 확인한다. 원문 AC-invite를 유지한다.
- 포함 범위: 초대 대상 이메일 입력, 권한에 따른 초대 요청, 요청 결과 확인. 재전송·만료·중복 처리는 관련 정책과 적용 범위가 미정인 채 보존하며 이번 명세에서 임의로 제외하지 않는다(Q-003~Q-005).
- 제외 범위와 근거: 실제 FE 구현과 서버 수정은 request.md의 명시적 제외다. 이번 실행에는 외부 자료 검색, 사용자 답변 요청, Git 작업, 게시, 브라우저 사용 및 위임도 포함되지 않는다.
- 적용 제약: 제공 자료만 사용한다. 코드·디자인 시스템·성능·접근성·반응형의 구체 제약은 제공되지 않았다. 화면 자료는 누락되었으며 추정 레이아웃이나 문구를 확정하지 않는다(Q-006).
- 현재→목표: 현재 앱의 동작은 관찰하지 않았다. 목표 동작은 AC-invite이고, 현재 배포 동작에 관한 진술이 아니다.

- OD-permission은 확정 정책이 아니다. 역할과 API 권한 오류 계약이 미정이며 담당자 확인은 보류되어 있다. Q-001의 deferred와 차단성을 유지한다.
- 개발자에게 남기는 구현 재량: 외부 동작이 확정된 후의 내부 컴포넌트 분할과 상태 보관 수단은 지정하지 않는다. 이 재량으로 역할·검증·결과 UI를 정할 수는 없다.
- 기존 코드/디자인 시스템 참조: 제공되지 않았고 접근 허용 범위에도 없어 미열람이다. 비적용으로 판정한 것이 아니다.

- 검토 대상: 이 SPEC revision 2, QUESTIONS revision 2, §2.1의 digest로 식별한 제공 파일 네 개. 최초 초안에 대한 한 차례 자기 검토 후 구조 형식만 한 차례 수정했다. 외부 동작·정책·질문 상태는 바꾸지 않았다.
- 준비 판정 이유: 필요한 네 가지 문서 검토를 수행했으나 Q-001(deferred) 및 Q-002~Q-008(open)이 AC-invite의 활성 차단이다. 자료가 없는 상태에서 ready로 올리거나 범위를 축소하지 않는다.
- 외부 의존·미확인 범위: 계약 자체의 결정/열람이 부족하다. 확정 계약의 미배포 문제라고 판정할 근거도 없다. 이미지·schema·후속 결정·코드·실서버는 미확인이다.
- 후속 검증: 결정 자료가 추가되면 관련 규칙·AC·질문 이력을 함께 갱신하고 재검토한다. 구현 시 원본 §6.1과 QUESTIONS를 직접 대조하여 AC 의미, 역할별 허용/거절, 입력 검증, 요청 payload/응답 매핑, 실패 후 회복과 확정된 예외 정책을 실제 앱에서 확인해야 한다. 이번에는 구현·실행 테스트·게시를 하지 않았다.
