## 2. 질문 상세

### Q-001 — 계약의 실제 배포 상태

- 원문 식별자: api.md:2의 “계약의 실제 배포 상태는 이 문서로 확인하지 않았습니다.”
- 질문: 구현/통합할 환경에서 이 Target contract v1 endpoint와 응답 계약을 실제로 사용할 수 있는가?
- 근거·충돌: SRC-002는 이번 기능의 확정 계약임을 명시한다. 계약 미정이라는 충돌은 없고 실제 배포 여부만 알 수 없다.
- 현재 확인한 사실: GET /api/projects와 네 status, 200 Project[], 503 {error:string}은 문서 계약이다. 실서버를 호출하지 않았다.
- 구현 영향: 실서버 연결·통합 검증 시 실행 환경·배포 시점을 확인해야 한다. 계약 기반 FE 구현과 제어 응답으로 AC 검증은 독립 진행 가능하다.
- 차단성 이유: 동작이나 schema 결정을 추측할 필요는 없다. 문서 준비는 배포 인증이 아니므로 준비 판정의 차단 조건이 아니다. 실서버 검증 성공을 미리 주장할 수는 없다.
- 해결에 필요한 것: 해당 환경에서 계약이 배포된 버전·endpoint 확인 또는 실제 요청/응답 검증 증거.
- 결정권자·답변자: unknown.
- 필요한 시점·재확인 조건: 실서버 통합 검증 이전, 또는 계약 판본/대상 환경 변경 시.
- 해결 결과: 답변·배포 증거 없음.
- SPEC 반영 위치: §2.1 SRC-002, §5.1, §6.1 확인 방법, §6.2의 미확인 범위.

### Q-002 — 초기 진입 관례의 확인

- 원문 식별자: request.md:2–5 및 selected-reference.png의 All·Tide 선택 정적 화면. 별도 OD-ID 없음.
- 질문: 기존 화면 진입 경로가 정하는 초기 필터·첫 조회 시점·프로젝트 미선택 상태의 표현은 무엇인가?
- 근거·충돌: SRC-001은 네 선택 값과 선택 후 결과를, SRC-002는 status 변경/Retry 요청을 정한다. SRC-005는 All과 Tide가 보이는 한 상태로, 초기값·자동선택·미선택 문구를 증명하지 않는다. 서로 충돌하는 확정 결정은 없다.
- 현재 확인한 사실: 사용자 선택 후 동작·필터/요청/결과 일치·선택 유지·empty/error·Retry·최신성은 모두 확정되어 있다. 기존 진입 코드/초기화 규칙은 제공되지 않았다.
- 구현 영향: 구현자가 기존 초기화 경로를 연결할 때 확인할 항목이다. 참고 이미지 때문에 Tide를 자동선택하거나 All을 강제 기본값으로 새로 만들지 않는다.
- 차단성 이유: 원 AC는 사용자가 필터 또는 프로젝트를 선택한 상태에서 모두 구현·검증할 수 있고 초기값 자체를 제한하지 않는다. 새 진입 정책을 요구하는 질문이 아니라 기존 동작을 임의 변경하지 않기 위한 통합 확인이다. 후속 요청이 특정 초기값/자동선택을 요구하면 그 결정의 영향과 차단성을 다시 판정한다.
- 해결에 필요한 것: 구현 대상의 기존 초기화/진입 코드 확인, 또는 사용자가 확정한 초기 진입 요구. 이 문서 작업은 sources만 읽도록 제한되어 있어 확인하지 않았다.
- 결정권자·답변자: unknown.
- 필요한 시점·재확인 조건: 기존 화면과 연결 시. 초기 진입 요구가 추가되면 SPEC §3~§5와 관련 AC를 재검토한다.
- 해결 결과: 실제 초기화 경로·기본값·미선택 문구 미확인. 제안·이미지 상태를 사용자 결정으로 채택하지 않았다.
- SPEC 반영 위치: §2.2, §4, §5.1, §6.1 검증 사전조건.
