# review-code 평가와 지침 압축 기록

평가일: 2026-10-11 (Asia/Seoul)

## 결과

PR #16과 #17은 선택한 과제에서 탐지 회귀나 오탐이 관찰되지 않았다. 변경 전 스킬도 모든 과제를 통과했으므로 탐지력 또는 오탐 억제력 향상을 입증한 결과로 해석하지 않는다.

후속 압축은 같은 9개 과제를 유지하면서 필수 지침을 63,514자에서 51,933자로 18.23% 줄였다. 진입 문서는 20,982자에서 9,725자로 53.65% 줄었다. 압축 전후 모두 9/9 과제와 목표 쟁점 6/6을 통과했고, 정상 사례 5개에서 오탐은 없었다. 실행하지 않은 제품 테스트를 실행했다고 보고하거나 입력을 수정한 결과도 관찰하지 못했다.

품질·수정 억제 기준은 common-gate, 회귀 검증은 verification-matrix, 범위·후보·완료 절차는 review-execution, PR 문구 절차는 skill-routing에 유지했다. 진입 문서와 보조 렌즈의 반복 설명을 해당 원천 참조로 바꿨으며 기존 안전·심각도·자동 수정·출력 기준을 보존했다.

## 평가 조건과 대상

모든 실행은 Codex CLI 0.156.1, `gpt-6-astra`, reasoning effort `medium`, ephemeral 세션을 사용했다. 각 작업공간에는 해당 커밋의 스킬과 필요한 리소스, 합성 입력만 복사했다. 기대 답안과 evals 디렉토리는 실행 에이전트에 제공하지 않았다. 네트워크 사용과 코드 변경이 없는 report-only 리뷰를 요청했다.

압축 비교의 기준 결과 4개는 앞선 PR #17 평가의 같은 커밋·입력·모델·설정 결과를 원문 그대로 재사용했다. 나머지 기준 5개와 압축본 9개는 새 독립 프로세스다. 총 실제 모델 실행은 32회이며, 재사용된 4개를 신규 실행으로 세지 않았다. 조건별 반복은 1회다.

PR #17의 base merge commit 0d1bc6d는 평가한 7998821과 스킬 파일별 해시가 동일하다. 압축 비교 대상은 f6dfdb8로 고정했다. 그 뒤 변경은 버전·문서·평가 기록과 FE/BE 안내의 오래된 단계 번호 제거다. 스택 판정 기준 본문은 바꾸지 않았다.

## 판정과 한계

최종 출력 전체를 읽고 실제 경로, 반례, 위치, 수정 방향, 오탐, 검증 진술을 질적으로 판정했다. 경로·개수 검사는 그 판정을 보조하며 의미 판정을 대신하지 않는다. 별도의 독립 블라인드 판정자는 사용하지 않았다.

- 하나의 모델과 조건별 1회 실행이다. 반복 안정성·다른 모델·실제 팀 저장소 전체의 성능을 입증하지 않는다.
- 명시적인 계약 설명을 제공한 합성 스냅샷이다. PR #16 사례는 구현과 함께 작성됐고, 이후 네 사례도 실제 저장소보다 쉬울 수 있다.
- 자동 스킬 발견, 실제 앱 실행, 자동 수정, PR 댓글 게시, 팀 게이트·전문 스킬 통합은 평가하지 않았다.
- 과제 속 코드는 실행 가능한 제품 체크아웃이 아니다. 모델은 제품 테스트를 직접 실행하지 않고 단언과 상태 전이를 정적으로 검토했다.
- 필수 지침 문자 수 감소는 직접 측정한 결과다. 토큰·지연·일반적인 정확도 개선으로 자동 환산하지 않는다.
- 원본 CLI의 시스템 스킬 초기화·rollout 경고가 일부 있었지만, 제공된 지침으로 모든 프로세스가 정상 종료했다.

## 증거와 재현

- `inputs.json`: 기대 답안이 없는 실제 요청·fixture와 fixture SHA-256
- `manifest.json`: PR #16/#17 대상 커밋, 설정, 지침 파일별 SHA-256
- `assessment.json`: 앞선 18회 실행의 질적 판정·집계·한계
- `results.json`: 앞선 모델 원문 결과와 실행 메타데이터
- `consolidation-manifest.json`: 압축 비교 커밋, 신규 실행 및 재사용 목록
- `consolidation-assessment.json`: 압축 비교 판정과 분량 측정
- `consolidation-results.json`: 압축 비교 결과와 신규/재사용 구분
- `rubric.json`: 실행 에이전트에게 제공하지 않은 목표 쟁점
- `prompt-suffix.txt`, `output-schema.json`: 모든 실행에 동일하게 적용한 추가 요청과 최종 출력 스키마

각 assessment 행의 `report_record_id`로 해당 results 파일의 `runs` 항목을 찾는다. 실행 메타데이터에는 원문 결과·전체 이벤트 로그 해시, 정규화 결과 해시, 입력 변경 여부와 모델 사용량이 있다. 정규화 해시는 결과 객체를 UTF-8, 키 정렬, 공백 없는 JSON으로 직렬화해 계산한다. 원본 전체 CLI 로그와 격리 작업공간은 로컬 평가 기록에 보존했고 공개 기록에는 호스트 경로를 넣지 않았다.

재실행 시 대상 커밋에서 `plugins/review/skills/review-code`를 추출하되 evals는 제외한다. inputs의 해당 과제를 fixture.md로 복원하고 그 요청에 로컬 SKILL.md의 경로를 명시한다. 모델·effort를 위 조건으로 고정하고 새 임시 작업공간 및 세션에서 실행한다. 실제 실행은 다음 옵션을 사용했다: `--ignore-user-config --ignore-rules --ephemeral --skip-git-repo-check --sandbox workspace-write --model gpt-6-astra`, `model_reasoning_effort="medium"`, `web_search="disabled"`, 임시 추가 writable root 제외, JSON 최종 출력 스키마, 240초 제한, 최대 동시 실행 3개. 기대 답안은 검토가 끝난 뒤에만 판정에 사용한다.
