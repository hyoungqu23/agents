# 한국어 상세 패턴 라우터

한국어 상세 규칙은 작성 주체를 판별하는 탐지기가 아니다. [한국어 기본 원칙](korean.md)만으로 처리하기 어려운 문제가 실제 문장에 보일 때, 아래 A–J 가운데 관련 범주만 골라 읽는다.

## 로딩 원칙

1. 먼저 [korean.md](korean.md)로 장르, 높임, 서법, 보호할 정보와 지배적인 문제를 파악한다.
2. 상세 파일을 열기 전에 원문에서 확인되는 증상을 한 문장으로 특정한다.
3. 그 증상에 직접 대응하는 범주만 읽는다. 보통 하나면 충분하고, 문제가 얽혔을 때만 둘 이상을 연다.
4. “혹시 있을지 모르는 문제”를 찾으려고 A–J를 전부 미리 읽지 않는다.
5. 사용자가 전 범주 감사를 명시했거나 긴 문서에서 여러 범주의 문제가 실제로 확인된 경우에만 범위를 넓힌다. 이때도 지배적인 범주부터 순차적으로 확인한다.
6. 패턴이 발견됐지만 보존과 수정이 애매할 때만 [korean-examples.md](korean-examples.md)를 읽는다.

## 범주 선택

| --- | --- | --- |
| A. 조사와 관계 표현 | `~에 대해`, `~을 통해`, 겹친 조사, 번역 어순 때문에 관계가 흐림 | [a-relations.md](korean-patterns/a-relations.md) |
| B. 주어·행위자·피동 | 책임 주체가 모호함, 겹피동, 추상명사가 행동을 가림 | [b-agency-passive.md](korean-patterns/b-agency-passive.md) |
| C. 명사화·약한 서술어 | 명사 사슬, `역할을 하다`, `것이다`, 유의어 순환이 행동을 감춤 | [c-nominalization-predicates.md](korean-patterns/c-nominalization-predicates.md) |
| D. 서법·확신·시간 | 가능성·의무·전망·시제가 뒤섞이거나 편집 중 주장 강도가 바뀜 | [d-modality-time.md](korean-patterns/d-modality-time.md) |
| E. 연결·수사 공식 | 빈 도입, 기계적 접속사, 억지 대조, 중요성 선언, 희망적 결말 | [e-rhetoric.md](korean-patterns/e-rhetoric.md) |
| F. 문장·단락 구조 | 긴 관형절, 모호한 지시어, 획일적 단락, 부적절한 목록·제목 | [f-sentence-paragraph.md](korean-patterns/f-sentence-paragraph.md) |
| G. 리듬·종결 | 같은 어미·길이·병렬·문장부호가 반복돼 생각의 관계가 평평해짐 | [g-rhythm-endings.md](korean-patterns/g-rhythm-endings.md) |
| H. 높임·화자·구어 | 높임이 흔들림, 인용 말투가 평탄화됨, 발표문이 문어체로 굳음 | [h-register-spoken.md](korean-patterns/h-register-spoken.md) |
| I. 전문용어·영어·표기 | 업계 용어를 어색하게 순화함, 영어가 장식이 됨, 표기가 흔들림 | [i-terminology-notation.md](korean-patterns/i-terminology-notation.md) |
| J. 형식·챗봇 잔여물 | 의례적 칭찬·구조 예고·마무리, 과한 굵게·이모지·표·불릿 | [j-format-chat.md](korean-patterns/j-format-chat.md) |

## 작업별 기본 경로

- **교정·가벼운 편집:** [korean.md](korean.md)만 사용한다. 명백한 문제를 설명하는 데 상세 규칙이 필요할 때만 해당 범주 하나를 연다.
- **일반 편집:** 먼저 원문에서 지배적인 문제를 찾고 관련 범주만 연다. “AI 티 제거”라는 요청만으로 공통 패턴과 A–J 전체를 읽지 않는다.
- **재작성:** 구조를 실제로 바꿔야 할 때 F를 우선 검토하고, 원문에 확인된 다른 범주만 더한다.
- **감사:** 정확한 구절로 입증할 수 있는 범주만 읽고 보고한다. 전 범주 감사를 명시하지 않았다면 발견되지 않은 범주까지 체크리스트처럼 훑지 않는다.
- **발표문·대화:** H를 우선한다. 호흡이나 병렬 문제가 실제로 있으면 G를 추가한다.
- **보고서·정책·고위험 문서:** 책임과 서법 문제가 있으면 B와 D를 우선한다. 위험도가 높거나 대규모 재구성이면 [evaluation.md](evaluation.md)도 읽는다.

## 범주가 얽힐 때

- 피동과 명사화가 함께 나오면 B와 C의 단어를 따로 치환하지 말고 책임 주체와 중심 동사를 먼저 찾는다.
- 접속사·대조·결론 공식이 단락 구조와 함께 반복되면 E를 먼저 보고, 문장 순서를 바꿔야 할 때만 F를 추가한다.
- 종결어미·문장 길이·불릿이 균일하면 G와 J의 겉모양보다 F의 정보 구조를 먼저 본다.
- 높임과 영어 혼용이 흔들리면 H와 I에서 독자·매체·브랜드 기준을 하나 정한다.

## 공통 판정

- **높음:** 문법, 수식 범위, 책임 주체, 뜻을 흐릴 가능성이 큰 문제
- **조건부:** 반복·밀도·장르에 따라 문제가 되는 표현
- **관찰:** 문서 전체의 분포로만 판단할 특징. 횟수나 비율을 목표로 고치지 않는다.

고유명사, 숫자, 날짜, 단위, 직접 인용, 법조문, 코드, 명령어, 식별자, 표준 약어는 보호한다. 각 규칙의 **수정 조건**과 **보존 조건**을 함께 적용하고, 가장 작은 의미 이동부터 시도한다.

## 감사 출력

패턴 ID만 나열하지 말고 다음 형식으로 보고한다.

`정확한 구절 → 패턴과 문맥 진단 → 독자가 겪는 문제 → 보존 조건을 고려한 수정 방향`

진단에는 해당되는 형식과 정보 문제를 구체적으로 이름 붙인다. 예를 들어 대조와 비유가 함께 근거를 가리면 둘 다 적는다. 수정 방향은 “구체화한다”나 “재검토한다”에서 멈추지 말고, 어떤 기능·비교·근거를 제시하거나 어떤 표현을 덜어 낼지 밝힌다.

같은 원인이 반복되면 대표 구절을 묶는다. 총점, AI 확률, 제거율은 제공하지 않는다. 사용자가 점수를 요구하면 이 기준에 대한 적합도일 뿐 작성 주체의 확률이 아니라고 밝힌다.
