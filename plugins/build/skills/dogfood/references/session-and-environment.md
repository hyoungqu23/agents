# Session and environment

Identify URL, environment, desired revision/PR set, actual served build, account/org/
role and backend separately, with the real observation method. Unknown remains
unknown. Multiple PRs, uncommitted local code, stale bundles and caches can make
checkout HEAD insufficient. Use nonsecret build/network/UI observations; do not
reset caches, switch user branches or restart a borrowed browser to force a match.

Wait for meaningful route/content/state rather than a fixed delay or networkidle
for every app. Separate missing server/login/permissions from product defects.
When target identity is required for a specific revision, missing proof leaves that
claim unverified even if other checks are useful. Local source fingerprints exclude
runtime build directories and do not authenticate a remote served bundle.

Choose a tool by the user's named session, existing login and needed features:
semantic/physical input, modifier actions, tabs, image delivery, network/console and
optional recording. Record version (or unavailable), capability, support yes/no/
unknown and help/schema/docs/runtime basis. Documentation-only support is untested.
Unsupported network or input features affect relevant checks, not all work.

Bind the actual browser/context/tab/window IDs, profile connection mode and origin.
A session name does not isolate OS focus or guarantee tab ownership. Recheck bindings
after tool switching, recording, login or profile changes. Use fresh refs/screens.
Existing CDP connection, profile-directory launch and profile copy are distinct.
Do not copy cookies or user profiles unless that execution method was authorized.

Preserve borrowed login/unsaved state. If task scope permits, a separately owned QA
tab in the same profile can avoid moving the user's working tab. A user-named tab
must be honored. One browser operator per shared profile; read-only image analysis
need not manipulate a tab. Stop only recordings/servers/resources you started.
