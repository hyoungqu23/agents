# Journeys and oracles

Build journeys as entry/actor/data → actions/conditions → distinguishable visible
result → reentry/persistent or downstream effect. Connect check IDs to original ACs
and expected source anchors. Use relevant success, alternate, boundary and recovery
paths, not a universal state matrix.

Observe before input; then act, wait for a meaningful change and observe again.
Record browser input, OS input, accessibility action and synthetic DOM dispatch
separately. A click acknowledgement or tool's text readback may verify delivery
without verifying the final task. Keyboard claims need actual focus traversal and
key behavior. Programmatic focus or DOM-event reproduction must be disclosed.

For selections test supported modifier/range/cancel behavior and contrast the same
endpoints individually. Do not assume held keys persist across CLI commands. For
saving inspect actual API delivery, saved values and reentry. For timeout/lost
response, inspect current state before repeating a write. An intended disabled
control is a useful normal contrast, not automatically a defect.

Use actual backend behavior; record API origin/environment and observation method.
Do not insert mocks, intercept responses or invoke app internals. Service Workers
may be ordinary PWA features. A missing network viewer means real communication is
unverified unless another actual observation supports it. A successful local UI
server cannot establish backend behavior it does not serve.
